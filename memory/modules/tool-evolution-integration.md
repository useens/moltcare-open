## 📋 进化任务 × 工具矩阵映射

### 1. 轻量进化（每4小时）

| 任务 | 工具 | 执行方式 | 输出 |
|------|------|----------|------|
| 健康检查 | `exec` (df, free, ps) | 主会话 | 状态报告 |
| ClawHub技能扫描 | `generic_extractor` | **子代理** | 更新列表 |
| 用户模式分析 | `memory_search` | 主会话 | user-profile.md更新 |
| 快速决策生成 | `memory_get` + 分析 | 主会话 | L1-L3决策执行 |

**工具链示例：**
```
cron触发 ──▶ exec检查系统 ──▶ 异常? ──▶ message通知用户
              │
              └──▶ sessions_spawn子代理 ──▶ generic_extractor扫描ClawHub
                                          ──▶ 保存结果
                                          ──▶ memory_search分析近期对话
                                          ──▶ 更新user-profile.md
```

## 🛠️ 工具链最佳实践

### 成本优化层级

| 优先级 | 工具类型 | 成本 | 使用策略 |
|--------|----------|------|----------|
| **P0** | 本地脚本 (`exec`, `read`) | **0 tokens** | 优先使用 |
| **P1** | 网页提取器 (`generic_extractor`) | **0 tokens** | 情报收集首选 |
| **P2** | 搜索API (`ddgr`, `web_search`) | ~50-100 tokens | API缺失时补充 |
| **P3** | LLM推理 (`memory_search`) | ~200-500 tokens | 分析/决策时使用 |

### 并行策略

```
串行(主会话): 决策、分析、验证
    │
    ├──▶ 并行子代理1: 情报收集A
    ├──▶ 并行子代理2: 情报收集B  
    └──▶ 并行子代理3: 情报收集C
              │
              ▼
         汇总分析(主会话)
```

### 错误处理

| 错误类型 | 处理工具 | 策略 |
|----------|----------|------|
| 提取超时 | `process` (kill) | 记录失败，下次重试 |
| API限流 | `cron` (延迟) | 指数退避重试 |
| 数据异常 | `memory_search` | 回退到上次已知良好状态 |
