## 一、性能特点分析

| 节点 | CPU | 内存 | 磁盘 | 特长 |
|------|-----|------|------|------|
| **主节点** | 4核 ARM | 24GB | 100GB | 大内存任务、持久存储 |
| **备用节点(森森)** | 8核 AMD x86 | 16GB | 39GB SSD | 计算密集型、高并发处理 |

### 任务分工建议

| 任务类型 | 推荐节点 | 理由 |
|----------|----------|------|
| 大模型运行/推理 | 主节点 | 24GB内存优势 |
| 编译/构建 | 备用节点 | 8核x86性能更强 |
| 数据分析/处理 | 备用节点 | CPU密集型 |
| 大文件存储 | 主节点 | 100GB磁盘 |
| 并发任务执行 | 备用节点 | 8核优势 |
| 复杂搜索/爬虫 | 备用节点 | 高并发能力 |

## 二、通信机制设计

### 2.1 通信渠道矩阵

```
┌─────────────────────────────────────────────────────────────┐
│                    主备节点通信架构                          │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│   主节点(VM)                    备用节点(森森)               │
│   ┌──────────────┐              ┌──────────────┐            │
│   │   主节点     │◄────────────►│   森森       │            │
│   │  (Primary)   │   多通道通信 │  (Standby)   │            │
│   └──────┬───────┘              └──────┬───────┘            │
│          │                              │                    │
│          ▼                              ▼                    │
│   ┌──────────────────────────────────────────┐              │
│   │           通信渠道                        │              │
│   ├──────────────────────────────────────────┤              │
│   │ 1. GitHub仓库    - 异步任务/结果交换      │              │
│   │ 2. HTTP API      - 实时任务分发           │              │
│   │ 3. Feishu消息    - 即时通知/简单指令      │              │
│   │ 4. 共享存储      - 大文件传输             │              │
│   └──────────────────────────────────────────┘              │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 各通信渠道用途

| 渠道 | 延迟 | 用途 | 场景 |
|------|------|------|------|
| **GitHub仓库** | 分钟级 | 任务队列、结果存储、配置同步 | 批量任务、数据持久化 |
| **HTTP API** | 秒级 | 实时任务分发、状态查询 | 即时任务、心跳检测 |
| **Feishu消息** | 秒级 | 即时通知、简单指令、告警 | 人工交互、紧急通知 |
| **共享存储** | 取决于存储 | 大文件传输、数据集共享 | 大模型文件、数据集 |

## 三、协作模式设计

### 3.1 主从模式（Master-Worker）

```
主节点作为Master，备用节点作为Worker

主节点：
  - 任务调度
  - 结果聚合
  - 状态监控
  - 大内存任务执行

备用节点：
  - 接收任务
  - 计算密集型处理
  - 返回结果
  - 并发执行多个子任务
```

### 3.2 对等协作模式

```
两个节点平等协作，根据任务特点自动分配

决策流程：
  任务到达
    ↓
  分析任务类型（CPU/内存/IO）
    ↓
  查询节点负载状态
    ↓
  自动分配到合适节点
    ↓
  执行 → 同步结果
```

### 3.3 故障转移模式（已设计）

主节点故障 → 备用节点接管（4小时内）

## 四、具体实施方案

### 4.1 GitHub仓库协作（已实现基础）

**文件结构**：
```
workspace/
├── .collaboration/
│   ├── task-queue/          # 任务队列
│   │   ├── pending/         # 待处理任务
│   │   ├── processing/      # 处理中任务
│   │   └── completed/       # 已完成任务
│   ├── results/             # 结果存储
│   └── status/              # 节点状态
│       ├── primary.json     # 主节点状态
│       └── standby.json     # 备用节点状态
```

**任务格式** (`task-queue/pending/task-001.json`)：
```json
{
  "task_id": "task-001",
  "type": "data-processing",
  "priority": "high",
  "target_node": "standby",
  "payload": {
    "script": "scripts/analyze-data.py",
    "args": ["--source", "data.csv"]
  },
  "created_at": "2026-02-14T14:20:00Z",
  "created_by": "primary"
}
```

### 4.3 任务分配策略

```python
# 自动任务分配决策
def assign_task(task):
    if task['type'] in ['llm-inference', 'large-file-processing']:
        # 需要大内存 → 主节点
        return 'primary'
    elif task['type'] in ['data-processing', 'compilation', 'web-scraping']:
        # CPU密集型 → 备用节点
        return 'standby'
    else:
        # 根据负载动态分配
        if get_primary_load() < get_standby_load():
            return 'primary'
        else:
            return 'standby'
```

## 五、特长发挥方案

### 5.1 备用节点特长：高并发计算

**适合任务**：
1. **批量数据处理** - 并行处理大量数据
2. **Web爬虫/情报收集** - 多线程并发抓取
3. **代码编译/构建** - 利用8核加速
4. **复杂计算** - 数据分析、机器学习训练
5. **并发子代理** - 同时运行多个任务

**实施方案**：
```bash
# 主节点提交任务到GitHub队列
echo '{"type":"web-scraping","target":"example.com"}' > .collaboration/task-queue/pending/task-001.json
git add . && git commit -m "添加任务: web-scraping" && git push

# 备用节点轮询检测，自动执行
./scripts/task-worker.sh
```

### 5.2 主节点特长：大内存持久化

**适合任务**：
1. **大模型运行** - 24GB内存加载大模型
2. **长期存储** - 100GB磁盘存储历史数据
3. **任务调度** - 管理任务队列和分配
4. **结果聚合** - 汇总多个节点结果

## 七、协作场景示例

### 场景1: 批量数据分析
```
用户: 分析最近一周的日志数据
    ↓
主节点: 存储日志文件(100GB空间)
    ↓
主节点: 拆分任务，提交到GitHub队列
    ↓
备用节点: 拉取任务，8核并行处理
    ↓
备用节点: 上传结果到GitHub
    ↓
主节点: 聚合结果，展示给用户
```

### 场景2: 大模型推理
```
用户: 使用大模型生成报告
    ↓
主节点: 加载大模型(需要24GB内存)
    ↓
主节点: 执行推理任务
    ↓
主节点: 保存结果
    ↓
备用节点: 同步结果(可选)
```

### 场景3: 并发情报收集
```
用户: 收集10个网站的信息
    ↓
主节点: 创建10个子任务
    ↓
备用节点: 8核并发爬取(同时8个)
    ↓
备用节点: 完成后上传结果
    ↓
主节点: 汇总展示
```
