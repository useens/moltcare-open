### 核心组件

| 组件 | 路径 | 说明 |
|------|------|------|
| 监控脚本 | `scripts/vm-status-monitor.sh` | 检测VM在线/离线状态 |
| 定时任务 | `vm-status-monitor-dual` | 每分钟执行，sessionTarget=isolated |
| 日志清理 | `log-cleanup-daily` | 每天凌晨2点执行 |
| 状态文件 | `/tmp/vm_monitor_state` | 记录上次状态 |
| 日志文件 | `/root/.openclaw/logs/vm-monitor.log` | 执行日志 |

### 工作流程

1. **检测阶段** (子代理)
   - 每分钟执行SSH检测（端口4444）
   - 对比当前状态与上次记录
   - 状态无变化 → 静默完成
   - 状态变化 → 发送通知到主会话

2. **通知阶段** (主会话)
   - 接收 `sessions_send` 消息
   - 解析 STATE=online/offline
   - 使用 `message` 工具发送双渠道通知

3. **静默机制**
   - 状态无变化时不发送任何消息
   - 仅记录日志到本地文件

**修复历程**:
- v1: 脚本尝试用 `openclaw` CLI发送通知 → 子代理中失败
- v2: 子代理直接用 `message` 工具 → 通道限制失败
- v3: 子代理用 `sessions_send` 通知主会话 → ✅ 成功

### 关键洞察

**隔离会话的限制**:
- 子代理 (isolated session) 无法直接访问外部通道
- `message` 工具在子代理中受限（飞书通道不可用）
- 解决方案：`sessions_send` → 主会话 → `message` 工具

**Token消耗**:
- 正常检测（无变化）: ~200 tokens/分钟
- 状态变化（双渠道）: ~800-1000 tokens/次
- 预估日均: <5000 tokens

### 后续优化方向

1. **故障自愈**: VM离线超5分钟自动尝试重启
2. **统计面板**: 每日/每周在线率报告
3. **预测维护**: 基于历史数据预测VM故障
