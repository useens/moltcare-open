**项目地址**: https://github.com/qwibitai/nanoclaw  
**Stars**: ~800 | **定位**: 个人AI助手，主打容器隔离安全

#### 核心架构

```
┌─────────────────────────────────────────────────────────────────┐
│                     NANOCLAW系统架构                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                    HOST PROCESS (Node.js)                │   │
│  │  ┌─────────────┐  ┌─────────────┐  ┌─────────────────┐  │   │
│  │  │   index.ts  │  │  db.ts      │  │ container-runner│  │   │
│  │  │ (Orchestrator│  │ (SQLite)    │  │  (容器生命周期)  │  │   │
│  │  └──────┬──────┘  └─────────────┘  └────────┬────────┘  │   │
│  └─────────┼────────────────────────────────────┼───────────┘   │
│            │                                    │                │
│  ┌─────────┴────────────────────────────────────┴───────────┐   │
│  │           APPLE CONTAINER / DOCKER (隔离)                 │   │
│  │  ┌─────────────────────────────────────────────────────┐  │   │
│  │  │              AGENT CONTAINER                        │  │   │
│  │  │  • Claude Agent SDK    • /workspace (挂载)          │  │   │
│  │  │  • 非root执行           • 文件系统IPC               │  │   │
│  │  │  • 网络无限制           • 30分钟超时                │  │   │
│  │  └─────────────────────────────────────────────────────┘  │   │
│  └───────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 安全模型对比

| 维度 | OpenClaw | NanoClaw | 优势方 |
|------|----------|----------|--------|
| **安全边界** | 应用层权限检查 | OS级容器隔离 | NanoClaw |
| **凭证保护** | allowlist机制 | 只读挂载+stdin传递 | NanoClaw |
| **会话隔离** | 进程级 | 容器级+目录隔离 | NanoClaw |
| **可审计性** | 日志记录 | 容器日志+挂载审计 | 平局 |
| **性能开销** | 低 | 中等（容器启动） | OpenClaw |

#### 关键创新

1. **容器隔离即安全**: 不依赖权限检查，直接使用OS级隔离
2. **按群组隔离**: 每个群组独立文件夹和会话
3. **挂载允许列表**: 外部配置，Agent无法修改
4. **Agent Swarms**: 首个支持多Agent协作的个人助手

#### 局限

- ❌ 仅支持macOS和Linux
- ❌ 容器内网络无限制
- ❌ Claude Code凭证可被Agent发现
- ❌ 单用户设计，企业场景受限

**项目地址**: https://github.com/jlia0/tinyclaw  
**Stars**: 1,349 | **Forks**: 183

#### 核心架构

```
┌─────────────────────────────────────────────────────────────┐
│                     消息渠道层                                │
│         (Discord, Telegram, WhatsApp, Heartbeat)           │
└────────────────────┬────────────────────────────────────────┘
                     │ 写入 message.json
                     ↓
┌─────────────────────────────────────────────────────────────┐
│                     队列协调层                                │
│              ~/.tinyclaw/queue/                              │
│     incoming/  →  processing/  →  outgoing/                 │
└────────────────────┬────────────────────────────────────────┘
                     │
                     ↓
┌─────────────────────────────────────────────────────────────┐
│                   代理并行处理层                              │
│                                                              │
│   Agent A          Agent B          Agent C                 │
│   ┌────────┐       ┌────────┐       ┌────────┐             │
│   │Promise │       │Promise │       │Promise │             │
│   │ Chain  │       │ Chain  │       │ Chain  │             │
│   └────┬───┘       └────┬───┘       └────┬───┘             │
│        └────────────────┴────────────────┘                  │
│                     并行执行                                 │
└─────────────────────────────────────────────────────────────┘
```

#### 核心创新

| 特性 | 描述 | OpenClaw对比 |
|------|------|--------------|
| **文件队列** | 使用文件系统实现可靠消息队列 | 内存队列 |
| **Promise Chain** | Per-Agent串行，跨Agent并行 | 待实现 |
| **团队链式执行** | `@teammate` 文本协议触发协作 | 待实现 |
| **TUI监控** | 实时可视化Agent状态 | Canvas/截图 |
| **多Provider** | Claude + Codex统一接口 | Claude为主 |

#### 代码模式提取

```typescript
// Promise Chain 并发模型
const agentProcessingChains = new Map<string, Promise<void>>();
const chain = agentChains.get(agentId) || Promise.resolve();
const newChain = chain.then(() => processMessage(msg));
agentChains.set(agentId, newChain);
```

#### 局限

- ❌ 单机限制，难以水平扩展
- ❌ `--dangerously-skip-permissions` 安全风险
- ❌ 依赖CLI内部状态，外部难以观测
- ❌ 无标准化技能市场

**关键指标**:

- 企业客户的安全合规要求

#### 🔴 威胁2: 多Agent团队协作 (TinyClaw)

**威胁描述**:
TinyClaw原生支持多Agent团队协作，通过Promise Chain实现并行处理，通过`@teammate`协议实现链式执行。

**潜在影响**:
- 需要多Agent协作的用户选择TinyClaw
- OpenClaw在复杂任务场景竞争力下降
- 团队协作成为Agent平台标配

**关键指标**:
- TinyClaw的Stars增长率(1,349+)
- 社区对多Agent协作的需求
- 企业团队使用场景

#### 🔴 威胁3: Skill供应链攻击

**威胁描述**:
11.9%的公开Agent技能包含恶意代码，skill.md文件本质上是未签名的可执行文档。

**潜在影响**:
- 用户信任危机

- 安全事件品牌损害

**关键指标**:
- 恶意技能发现率
