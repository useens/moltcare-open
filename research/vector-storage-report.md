# 本地向量存储方案调研报告

> 调研时间：2026-02-09
> 调研范围：LanceDB、SQLite-vec、开源向量数据库、本地嵌入模型

---

## 一、各方案详细分析

### 1. LanceDB 纯本地模式

**简介**
LanceDB 是一个开发者友好的开源嵌入式检索库，专为多模态 AI 设计。它构建在 Lance 列式存储格式之上，支持向量搜索、全文搜索和 SQL 查询。

**本地模式特点**
- **完全开源**：100% 开源，无供应商锁定
- **嵌入式架构**：无需独立服务器，直接嵌入应用程序
- **多语言支持**：Python、TypeScript/JavaScript、Rust SDK
- **列式存储**：基于 Lance 格式，支持高效的存储和分析
- **零拷贝**：自动版本控制，无需额外基础设施管理数据版本

**优点**
| 优势 | 说明 |
|------|------|
| 性能优异 | 毫秒级搜索数十亿向量，支持 GPU 构建索引 |
| 多模态支持 | 支持文本、图像、视频、点云等多模态数据 |
| 生态丰富 | 与 LangChain、LlamaIndex、Pandas、Polars、DuckDB 等集成 |
| 混合搜索 | 支持向量相似度搜索 + 全文搜索 + SQL 过滤 |
| 无服务器依赖 | 纯本地运行，无需 Docker 或外部服务 |

**缺点**
| 劣势 | 说明 |
|------|------|
| 相对年轻 | 项目较新，生态成熟度不如 Milvus 等 |
| 分布式能力 | 纯本地模式不支持分布式，需要企业版 |
| 学习曲线 | 列式存储概念需要一定学习成本 |

**适用场景**
- 本地 AI/ML 应用开发
- 多模态数据处理
- 需要混合搜索（向量+全文+SQL）的场景
- 对延迟敏感的边缘部署

---

### 2. SQLite-vec 轻量级方案

**简介**
SQLite-vec 是一个极小的 SQLite 扩展，用于向量搜索。它是 sqlite-vss 的继任者，由 Mozilla Builders 项目赞助开发。

**核心特点**
- **纯 C 编写**：无依赖，可在任何 SQLite 运行的地方运行
- **超轻量级**：体积极小，适合嵌入式设备
- **多平台**：Linux/MacOS/Windows、浏览器 WASM、Raspberry Pi
- **纯 SQL 接口**：无需额外配置，使用标准 SQL 操作

**优点**
| 优势 | 说明 |
|------|------|
| 极简部署 | 单文件扩展，加载即用 |
| 跨平台 | 支持 WASM，可在浏览器中运行 |
| 语言绑定丰富 | Python、Node.js、Ruby、Go、Rust、Deno/Bun |
| SQLite 生态 | 可利用 SQLite 的完整生态和工具链 |
| 资源占用极低 | 适合 IoT 和移动设备 |

**缺点**
| 劣势 | 说明 |
|------|------|
| 功能相对简单 | 主要专注 KNN 搜索，高级功能有限 |
| 性能上限 | 不适合超大规模（十亿级）向量检索 |
| 预发布状态 | v1 之前，API 可能有破坏性变更 |
| 无内置嵌入 | 需配合 sqlite-lembed 或外部模型 |

**适用场景**
- 移动应用本地向量搜索
- IoT/边缘设备
- 浏览器端向量搜索（WASM）
- 小型项目或原型开发
- 需要 SQLite 兼容性的场景

### 3. 其他开源向量数据库对比

#### Chroma

**特点**
- 专为 AI 应用设计的向量数据库
- 支持内存模式和持久化模式
- Python/TypeScript/Rust SDK
- 内置嵌入函数支持（OpenAI、Hugging Face 等）

**优点**
- API 设计简洁，开发者体验好
- 与 LLM 应用框架集成度高
- 支持客户端-服务器模式部署

**缺点**
- 相对年轻，功能不如成熟数据库丰富
- 大规模生产环境验证较少

#### Qdrant

**特点**
- 用 Rust 编写的高性能向量数据库
- 支持过滤、payload 存储、分布式部署
- 提供云服务和自托管选项
- 丰富的客户端库（Python、Go、Rust、TypeScript 等）

**优点**
- 性能优秀，Rust 实现
- 功能丰富（过滤、聚合、推荐）
- 生产环境稳定

**缺点**
- 需要服务器部署（即使本地也需要启动服务）
- 相比纯嵌入式方案，部署复杂度稍高

#### Milvus/Zilliz

**特点**
- 企业级分布式向量数据库
- 功能最全面，生态系统最成熟
- 支持十亿级向量检索

**缺点**
- 需要 Docker/Kubernetes 部署
- 资源占用较高
- 不适合纯本地轻量级场景

### 4. 嵌入模型本地部署方案

#### Sentence-Transformers (SBERT)

**简介**
由 Hugging Face 维护的 Python 库，用于访问、使用和训练最先进的嵌入和重排序模型。

**特点**
- **10000+ 预训练模型**：Hugging Face 上可直接使用
- **MTEB 排行榜**：包含许多最先进的模型
- **三种模型类型**：
  - Embedding Models（双编码器）
  - Cross-Encoder/Reranker（重排序）
  - Sparse Encoder（稀疏嵌入，如 SPLADE）

**推荐模型**
| 模型 | 维度 | 特点 | 适用场景 |
|------|------|------|----------|
| all-MiniLM-L6-v2 | 384 | 轻量、快速 | 通用场景、资源受限 |
| all-mpnet-base-v2 | 768 | 质量更高 | 追求精度的场景 |
| BAAI/bge-large-zh | 1024 | 中文优化 | 中文文本处理 |
| BAAI/bge-small-zh | 512 | 轻量中文 | 中文移动端 |

**性能优化**
- ONNX 导出加速推理
- 量化（INT8）减少内存占用
- 批处理提高效率

#### 其他本地嵌入方案

| 方案 | 特点 |
|------|------|
| **Ollama** | 本地运行各种嵌入模型，REST API 接口 |
| **llama.cpp** | C++ 实现，支持 GGUF 格式，极轻量 |
| **sqlite-lembed** | SQLite 扩展，本地 GGUF 模型嵌入 |
| **FlagEmbedding** | 百度开源，中文场景表现优秀 |

## 二、技术栈组合推荐

### 推荐方案 A：轻量级全能组合 ⭐（最推荐）

**组合**：LanceDB + Sentence-Transformers

```
向量数据库：LanceDB (本地嵌入式)
嵌入模型：sentence-transformers (all-MiniLM-L6-v2 或 BAAI/bge 系列)
部署方式：纯 Python 依赖，pip install 即可
```

**优势**：
- 零服务器部署，纯 Python 环境
- 性能优异，支持百万级向量
- 支持多模态和混合搜索
- 生态丰富，与 LangChain/LlamaIndex 无缝集成

**适用**：大多数本地 AI 应用、RAG 系统、多模态搜索

---

### 推荐方案 B：极简轻量组合

**组合**：SQLite-vec + sqlite-lembed 或轻量 ONNX 模型

```
向量数据库：sqlite-vec (SQLite 扩展)
嵌入模型：sqlite-lembed (SQLite 扩展) 或 ONNX Runtime
部署方式：C 扩展 + 可选的本地模型
```

**优势**：
- 体积极小，适合嵌入式设备
- 单文件数据库，易于备份和迁移
- 跨平台（包括 WASM）

**适用**：移动应用、IoT 设备、浏览器端、小型工具

---

### 推荐方案 C：企业级生产组合

**组合**：Qdrant/Chroma + Sentence-Transformers

```
向量数据库：Qdrant (本地服务器模式) 或 Chroma (持久化模式)
嵌入模型：sentence-transformers (大型模型如 bge-large)
部署方式：Docker 或本地服务
```

**优势**：
- 功能最全面
- 生产环境验证充分
- 支持分布式扩展

**适用**：企业级应用、大规模生产环境

## 四、最终推荐

### 🏆 最适合本项目的方案：LanceDB + Sentence-Transformers

**选择理由**：

1. **纯本地零依赖**：无需 Docker、无需服务器，pip install 即可运行
2. **性能与功能平衡**：支持百万级向量检索，同时提供全文搜索、SQL 过滤等高级功能
3. **多模态原生支持**：如果未来需要处理图像、视频等非文本数据，无需更换架构
4. **生态集成**：与 LangChain、LlamaIndex 等主流框架无缝集成
5. **嵌入模型灵活**：通过 sentence-transformers 可使用超过 10000 个预训练模型，包括中文优化的 BGE 系列

**技术栈细节**：
```python
# 核心依赖
lancedb>=0.15.0
sentence-transformers>=3.0.0

# 推荐模型（中文场景）
BAAI/bge-small-zh-v1.5  # 512维，轻量快速
BAAI/bge-large-zh-v1.5  # 1024维，精度更高

# 推荐模型（英文/通用场景）
all-MiniLM-L6-v2        # 384维，平衡速度和质量
all-mpnet-base-v2       # 768维，更高质量
```

**备选方案**：
- 如果资源极其受限（如树莓派、移动设备），使用 **SQLite-vec + 轻量 ONNX 模型**
- 如果需要分布式或云服务，考虑 **Qdrant**
