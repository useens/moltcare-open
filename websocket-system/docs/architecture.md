# WebSocket 即时通信系统架构设计文档

## 1. 系统概述

### 1.1 设计目标
- 云端节点（Cloud Node）与本地节点（Local Node）之间实现低延迟（<100ms）双向通信
- 支持无人值守的自动对话机制
- 高可靠性：自动重连、心跳检测、断线恢复
- 安全性：TLS加密传输、Token身份验证

## 2. 角色分配

### 2.1 云端节点 (WebSocket Server)
| 组件 | 职责 |
|------|------|
| WebSocket Server | 监听连接请求，维护客户端连接池 |
| Auth Middleware | Token验证，拒绝非法连接 |
| Heartbeat Manager | 监控客户端心跳，检测超时断开 |
| Message Router | 根据消息类型路由到对应处理器 |
| Connection Manager | 管理活跃连接，支持按节点ID查找 |

### 2.2 本地节点 (WebSocket Client)
| 组件 | 职责 |
|------|------|
| Connection Handler | 建立/维护与服务器的连接 |
| Reconnect Manager | 实现指数退避重连策略 |
| Heartbeat Sender | 定时发送心跳包 |
| Message Handler | 处理接收到的消息，执行对应动作 |
| Auto-Dialog Engine | 无人值守时的自动响应逻辑 |

## 3. 通信流程

### 3.1 连接建立流程
```
本地节点                    云端节点
    │                          │
    │───── 1. TCP连接 ─────────>│
    │                          │
    │───── 2. TLS握手 ─────────>│
    │<──── 3. TLS完成 ──────────│
    │                          │
    │───── 4. WS握手 + Token ──>│
    │                          │──┐
    │                          │  │ 验证Token
    │<──── 5. 认证结果 ─────────│<─┘
    │                          │
    │<──── 6. 连接确认 ─────────│
    │                          │
    │◄════════════════════════►│  WebSocket连接建立
```

### 3.2 消息通信流程
```
本地节点                    云端节点
    │                          │
    │───── Heartbeat (30s) ────>│  周期性心跳
    │<──── Heartbeat ACK ───────│
    │                          │
    │───── Request ────────────>│  业务消息
    │<──── Response ────────────│  响应消息
    │                          │
    │<──── Server Push ─────────│  服务器主动推送
    │───── Ack ────────────────>│  确认接收
```

### 3.3 断线重连流程
```
检测到断开
    │
    ▼
┌─────────────┐
│ 等待退避时间 │◄─────┐
│ (指数退避)  │      │
└──────┬──────┘      │ 再次失败
       ▼              │
┌─────────────┐       │
│ 尝试重新连接 │───────┘
└──────┬──────┘
       ▼
   连接成功 ──► 恢复通信
```

## 4. 性能指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 连接延迟 | <100ms | 从TCP连接到WS握手完成 |
| 消息往返延迟 | <50ms | 端到端消息RTT |
| 心跳间隔 | 30s | 保持连接活跃 |
| 心跳超时 | 90s | 3个心跳周期无响应则断开 |
| 重连退避 | 指数退避 | 1s, 2s, 4s, 8s... 最大60s |
| 最大并发 | 10,000 | 单服务器支持连接数 |

## 5. 安全设计

### 5.1 传输层安全
- 使用 TLS 1.2/1.3 加密所有通信
- 证书由受信任CA签发或自签名
- 禁用弱密码套件

### 5.2 认证机制
- 基于 Token 的身份验证
- Token 格式: JWT 或随机字符串
- Token 通过 HTTP Header `Authorization` 或 URL 参数传递
- Token 过期时间: 24小时

### 5.3 访问控制
- IP 白名单（可选）
- 单节点单连接（踢除旧连接）
- 连接数限制

## 6. 扩展性设计

### 6.1 水平扩展
- 使用 Redis 存储连接状态，支持多服务器部署
- 负载均衡器分发 WebSocket 连接

### 6.2 消息队列
- 重要消息可持久化到 Redis/RabbitMQ
- 离线消息支持（未来扩展）

## 7. 监控与日志

### 7.1 监控指标
- 活跃连接数
- 消息吞吐量 (msg/s)
- 平均延迟
- 重连次数
- 错误率

### 7.2 日志级别
- DEBUG: 详细调试信息
- INFO: 连接/断开、重要事件
- WARNING: 异常但可恢复
- ERROR: 需要人工介入
