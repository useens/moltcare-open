# WebSocket系统测试验证方案

## 1. 测试目标

验证WebSocket系统的功能完整性、性能指标和可靠性要求。

## 2. 测试环境

### 2.1 硬件要求
- **云端节点**: 2核4G云服务器，公网IP
- **本地节点**: 树莓派或普通PC，内网环境
- **网络**: 互联网连接，延迟 <50ms

### 2.2 软件环境
- Python 3.8+
- websockets 库
- psutil 库

## 3. 测试项目

### 3.1 功能测试

| 测试项 | 测试方法 | 预期结果 | 通过标准 |
|--------|----------|----------|----------|
| 连接建立 | 客户端连接服务器 | 连接成功 | 平均延迟 <100ms |
| 认证流程 | 发送auth消息 | 收到auth_response | success=true |
| 心跳机制 | 观察30秒心跳 | 收到heartbeat_ack | 成功率100% |
| 消息收发 | 发送request | 收到response | RTT <50ms |
| 自动响应 | 发送get_status | 自动返回状态 | 响应时间 <100ms |
| 断线检测 | 断开网络 | 检测到断线 | 90秒内触发 |
| 自动重连 | 恢复网络 | 自动重连成功 | 指数退避 |

### 3.2 性能测试

| 测试项 | 指标 | 目标值 | 测试方法 |
|--------|------|--------|----------|
| 连接延迟 | 平均 | <100ms | 10次连接取平均 |
| 消息RTT | 平均 | <50ms | 20次ping取平均 |
| 并发连接 | 同时在线 | 100+ | 100客户端并发 |
| 吞吐量 | 消息/秒 | 1000+ | 压力测试 |
| 内存占用 | 单连接 | <1MB | 监控统计 |

### 3.3 可靠性测试

| 测试项 | 测试方法 | 通过标准 |
|--------|----------|----------|
| 长时间运行 | 7×24小时 | 无内存泄漏 |
| 网络抖动 | 模拟丢包 | 自动恢复 |
| 服务器重启 | 重启服务端 | 客户端自动重连 |
| 客户端重启 | 重启客户端 | 新连接建立 |

## 4. 测试执行

### 4.1 自动化测试

```bash
# 运行完整测试套件
python tests/test_websocket.py --url ws://server:8765

# 测试报告将保存到 test_results.json
```

### 4.2 手动测试

```bash
# 1. 启动服务器
python src/server.py --host 0.0.0.0 --port 8765

# 2. 启动多个客户端
python src/client.py --url ws://localhost:8765 --node-id node-1 &
python src/client.py --url ws://localhost:8765 --node-id node-2 &

# 3. 使用wscat或浏览器测试
wscat -c ws://localhost:8765
```

## 6. 问题排查

### 6.1 连接失败

1. 检查服务器端口是否开放
2. 检查防火墙规则
3. 验证Token是否正确
4. 查看服务器日志

### 6.2 心跳超时

1. 检查网络稳定性
2. 调整心跳间隔
3. 检查服务器负载

### 6.3 性能下降

1. 检查内存使用
2. 检查CPU负载
3. 查看网络带宽
4. 优化消息大小

## 7. 测试通过标准

所有测试项必须满足以下条件：

- ✅ 功能测试100%通过
- ✅ 连接延迟 <100ms
- ✅ 消息RTT <50ms  
- ✅ 并发100+连接稳定
- ✅ 7×24小时无故障运行
