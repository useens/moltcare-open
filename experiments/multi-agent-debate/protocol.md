# Multi-Agent 实时讨论协议 (方案B)

## 共享状态存储结构

```
/experiments/multi-agent-debate/
├── shared/
│   ├── round-1/           # 第一轮发言
│   │   ├── harper.md      # Harper的初始分析
│   │   ├── benjamin.md    # Benjamin的初始架构
│   │   └── lucas.md       # Lucas的初始实现思路
│   ├── round-2/           # 第二轮：回应与质疑
│   │   ├── harper.md      # Harper回应他人
│   │   ├── benjamin.md    # Benjamin回应他人
│   │   └── lucas.md       # Lucas回应他人
│   ├── round-3/           # 第三轮：达成共识
│   └── consensus.md       # 最终共识总结
├── rules.md               # 讨论规则
└── status.json            # 实时状态监控
```

## 讨论规则

1. **每轮时限**：2分钟
2. **发言格式**：
   ```markdown
   ## [时间戳] 发言人
   
   ### 我的观点
   - 要点1
   - 要点2
   
   ### 对他人的回应
   - @Benjamin: 关于XX点，我认为...
   - @Lucas: 补充说明...
   
   ### 提出的质疑
   - 质疑JWT的安全性...
   
   ### 建议方案
   - 建议采用...
   ```

3. **轮次推进**：
   - Round 1: 各自独立分析（并行）
   - Round 2: 读取他人Round 1，提出质疑/补充
   - Round 3: 基于Round 2的讨论，达成共识或妥协

4. **结束条件**：
   - 3轮讨论完成
   - 或队长判断已达成共识
   - 或超时（每轮2分钟，最多6分钟）

## 专家角色强化

**Harper (研究专家)**:
- 负责：技术选型、数据支持、外部资料引用
- 关注：可行性、性能数据、最佳实践
- 质疑点："这个方案有数据支持吗？"

**Benjamin (架构专家)**:
- 负责：整体设计、安全考量、长期可维护性
- 关注：架构合理性、扩展性、安全性
- 质疑点："这个设计是否符合分层原则？"

**Lucas (实现专家)**:
- 负责：代码可行性、实现复杂度、工期评估
- 关注：能否实现、实现成本、潜在坑点
- 质疑点："这个方案实现起来要多久？"
