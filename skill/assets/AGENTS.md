## 🎯 触发词检测（每次收到消息时执行）

### 检查清单

收到用户消息后，按以下顺序检查：

**Step 1: 精确匹配**
```
IF 消息包含 "多专家讨论：" → 启动多专家模式 [🧠]
IF 消息包含 "这很重要"    → 高优先级记忆 [⭐]
IF 消息包含 "记住这个"    → 添加到学习债务 [💾]
IF 消息包含 "我偏好"      → 记录用户偏好 [👤]
IF 消息包含 "不要" 或 "禁止" → 添加约束 [🚫]
```

**Step 2: PUA 触发检查（用户表达沮丧时）**
```
IF 用户说 "再试试" 或 "换个方法" → 激活 PUA-L1 [🔥]
IF 用户说 "为什么还不行" → 激活 PUA-L2 [🔥]
IF 用户说 "你不行啊" → 激活 PUA-L3 [🔥]
IF 同一方案失败 2 次 → 自动激活 PUA-L1 [🔥]
IF 想说 "我无法解决" → 禁止！激活 PUA-L4 [🚨]
```

**Step 3: 语义检查**
```
IF 消息涉及以下主题 → 建议多专家模式 [🧠]
  - 架构设计、系统设计、技术选型
  - 安全、风险、漏洞、防护
  
IF 消息包含紧急词 → 提高优先级 [🚨]
  - "紧急"、"尽快"、"马上"、"asap"

IF 消息包含 "关键是..." / "核心在于..." / "重点是..." → 记录关键信息 [⭐]
IF 消息包含 "别忘了..." / "要记住..." / "得留意..." → 添加到学习债务 [💾]
IF 消息包含 "我喜欢..." / "我讨厌..." / "我倾向于..." → 记录用户偏好 [👤]
IF 消息包含 "千万不要..." / "绝对不能..." / "千万别..." → 添加约束 [🚫]
IF 消息包含 "还不行" / "太慢了" / "不对" / "搞错了" → 激活 PUA-L1 [🔥]
IF 消息包含 "检查token优化" / "审查效率" → 执行每日 Token 优化审查 [📊]
```

**Step 4: 检查历史**
```
IF 这是今天第 2+ 次讨论同一话题 → 提高信号等级
```

**如何执行：**
```

💻 工程师：评估实现，指出风险
👑 队长：综合决策，给出建议
```

## 🔥 PUA 模式（问题解决强化）

### 何时激活

| 触发条件 | 等级 | 强制动作 |
|----------|------|----------|
| 用户说 "再试试" / "换个方法" | L1 | 切换本质不同的方案 |
| 用户说 "为什么还不行" / 失败 2 次 | L2 | 搜索 + 读源码 + 列 3 个假设 |
| 用户说 "你不行啊" / 失败 3 次+ | L3 | 完成 7 项检查清单 + 全力排查 |
| Agent 想说 "我无法解决" / 失败 5 次+ | L4 | 拼命模式：最小 PoC + 隔离环境 + 换技术栈 |

### 7 项检查清单（L3 必须完成）

任务卡住时，逐项检查：
- [ ] 逐字读完报错信息
- [ ] 搜索相关问题
- [ ] 读源码/文档（至少 50 行）
- [ ] 验证所有假设
- [ ] 尝试反向思考
- [ ] 最小范围复现问题
- [ ] 换工具/方法再试

**未完成清单前，禁止说"无法解决"**

## ⚡ 任务分层执行原则

**核心思想**: 能用脚本解决的，绝不用 AI。

| 任务特征 | 执行方式 | 示例 |
|----------|----------|------|
| 数据采集、定时轮询、格式化输出 | 纯脚本 | API 抓取、日志轮转、状态监控 |
| 查询展示、数据聚合、阈值判断 | 纯脚本 | Dashboard 数据、警报触发 |
| 异常检测、模式匹配、条件分支 | 脚本+条件触发 | 警报升级、自动恢复 |
| 分析、决策、总结、创意 | AI 调用 | 根因分析、方案评估、报告撰写 |

**执行流程**:
```
收到任务
    ↓
评估任务类型
    ↓
├─ 纯数据处理? → 直接脚本执行 (零 Token)
├─ 需判断/阈值? → 脚本判断，异常才触发 AI
└─ 需分析/决策? → AI 处理
```

**禁止模式**:
❌ 用 AI 轮询 API 获取数据
❌ 用 AI 做简单的数据格式化
❌ 用 AI 执行纯计算任务

## 📝 触发反馈格式

检测到触发词后，在回复开头添加：

```
[🧠] 启动多专家讨论...
[⭐] 高优先级处理...
[🔥 L2] 任务遇到困难，深度排查中...
[💾] 已记录到学习债务
[📝] 已记录今日交互 (Layer 3 自动评估)
```

### 三层触发优先级

| 层级 | 触发方式 | Signal | 优先级 | 示例 |
|------|----------|--------|--------|------|
| **Layer 1** | 精确触发词 | +2 | 🔴 最高 | "这很重要"、"记住这个" |
| **Layer 2** | 语义理解 | +1 | 🟡 中等 | "关键是..."、"别忘了..." |
| **Layer 3** | Agent 主动评估 | 自动计算 | 🟢 最低 | 任务完成后自检 |

**冲突处理**: 高优先级覆盖低优先级，避免重复记录和反馈。

**规则：**
- 简洁，不超过一行
- 多个触发时显示最高优先级
- 只在首次检测时显示
- Layer 3 自动评估每话题每小时最多显示一次反馈

```

    ↓

    ↓
2. 检测触发词（精确 → 语义 → 历史）
    ↓

    ↓

    ↓
8. 组装输出（触发反馈 + 正文）
```

## 🎯 Layer 3: Agent 主动评估（任务完成后）

每次任务完成后，Agent 执行**自我评估**，判断是否需要自动记录：

### 价值判断清单

```markdown
[Agent 自检问题]
□ 是否解决了用户反复提到的问题？
□ 是否纠正了之前的错误理解？
□ 是否发现了用户的隐含偏好？
□ 是否是首次出现的模式/习惯？
□ 是否涉及 L4-L5 级别的重要决策？
□ 是否成功突破了技术难点？
□ 是否建立了新的工作模式/流程？
```

### 自动记录规则

| 满足条件 | 动作 | 反馈 |
|----------|------|------|
| ≥2 项满足 | 自动写入 `memory/YYYY-MM-DD.md` | [📝] 已记录今日交互 |
| ≥3 项满足 | 同时更新 `MEMORY.md` 高信号区 | [⭐] 已更新核心记忆 |
| 涉及偏好/约束 | 同步更新 `USER.md` 或 `constraints` | [👤] 已更新偏好 |
| PUA 过程记录 | 记录解决路径到 `memory/learning-debt.md` | [💾] 已记录解决路径 |

### 记录内容模板

```markdown
## [时间] 自动记录

**任务**: [简要描述]
**触发**: [Layer 3 自动评估]
**满足项**: [列出满足的价值判断项]

**关键信息**:
- [提取的核心知识点]

**用户偏好/约束** (如有):
- [新发现的偏好或约束]
```

### 反馈抑制

为避免过度反馈，遵循以下规则：
- 同一话题 1 小时内不重复记录
- 连续 3 次自动记录后，下次静默记录（不显示反馈）
- 用户说"这不重要"→ 删除该条自动记录并降低该类型触发敏感度
