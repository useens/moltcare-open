# BEST_PRACTICES.md - Agent 效率最佳实践

> 🚀 用最小的 Token 成本，完成最大的工作价值

## 一、任务分层决策树

```
任务输入
    │
    ├─→ 是否纯数据处理?
    │   ├─→ 是 → 脚本执行 (L0)
    │   └─→ 否 → 继续判断
    │
    ├─→ 是否可规则化?
    │   ├─→ 是 → 脚本+条件触发 (L1-L2)
    │   └─→ 否 → AI 处理 (L3)
    │
    └─→ 是否需理解/推理?
        ├─→ 是 → AI 处理 (L3)
        └─→ 否 → 考虑规则化后降级
```

---

## 二、各层最佳实践

### L0: 纯脚本层 (零 Token)

**适用场景**:
- API 数据抓取
- 定时任务执行
- 日志收集与轮转
- 简单的数据转换
- 状态监控与上报

**设计原则**:
1. **幂等性**: 脚本可重复执行，结果一致
2. **防御性**: 处理边界情况和异常数据
3. **可观测**: 输出结构化日志，便于追踪
4. **资源隔离**: 避免阻塞主 Agent 会话

**实现方式**:
```bash
# cron 定时执行
*/5 * * * * /path/to/script.sh >> /var/log/task.log 2>&1

# 或 OpenClaw 内置调度
{
  "jobs": [{
    "schedule": { "kind": "every", "everyMs": 300000 },
    "delivery": { "mode": "ifOutput" }
  }]
}
```

---

### L1: 查询展示层 (零 Token)

**适用场景**:
- 状态查询与展示
- 数据聚合与统计
- 格式化输出
- 简单的条件筛选

**设计原则**:
1. **预计算**: 常用数据提前计算存储
2. **缓存优先**: 检查缓存，避免重复计算
3. **增量更新**: 只处理变化的部分
4. **延迟加载**: 按需加载，避免全量扫描

**实现示例**:
```javascript
// 优先读取缓存
const cache = readCache(key);
if (cache && !isExpired(cache)) {
  return cache.data;
}

// 缓存未命中才计算
const data = computeExpensiveOperation();
writeCache(key, data);
return data;
```

---

### L2: 条件触发层 (按需 Token)

**适用场景**:
- 阈值监控与警报
- 异常检测与通知
- 自动故障恢复
- 升级策略执行

**设计原则**:
1. **分层阈值**: 警告 → 严重 → 紧急
2. **防抖机制**: 避免频繁触发
3. **上下文传递**: 触发时携带足够上下文
4. **降级策略**: 异常时有备用方案

**实现模式**:
```javascript
function checkThresholds(value) {
  // 纯脚本判断，零 Token
  if (value > CRITICAL) {
    // 只有达到阈值才触发 AI
    triggerAIAnalysis({
      level: 'critical',
      value: value,
      context: getContext()
    });
    return { alert: true, level: 'critical' };
  }
  
  if (value > WARNING) {
    return { alert: true, level: 'warning' };
  }
  
  return { alert: false };
}
```

---

### L3: AI 决策层 (正常 Token)

**适用场景**:
- 复杂问题分析
- 方案评估与选择
- 根因分析
- 总结与报告撰写
- 创意与生成任务

**设计原则**:
1. **上下文精简**: 只传递必要信息
2. **结构化输入**: 使用模板规范输入
3. **结果缓存**: 相似问题复用结论
4. **渐进式加载**: 先概要，再深入

## 三、Token 优化技巧

### 1. 批处理聚合

❌ **低效**: 每条数据都问 AI
```
"这条记录正常吗?"
"这条呢?"
...
```

✅ **高效**: 脚本预处理，AI 只看异常
```
"共 1000 条记录，脚本筛选出 3 条异常，请分析: [...]"
```

### 2. 预格式化输出

❌ **低效**: AI 处理原始数据
```
原始 JSON 数据 → AI → "整理成表格"
```

✅ **高效**: 脚本格式化，AI 专注分析
```
脚本生成表格 → AI → "分析趋势并给出建议"
```

### 3. 分层缓存策略

| 缓存类型 | 适用数据 | 有效期 |
|----------|----------|--------|
| 内存缓存 | 高频查询 | 分钟级 |
| 文件缓存 | 中频数据 | 小时级 |
| 持久化存储 | 低频/历史 | 天级 |

### 4. 增量更新模式

```javascript
// 只处理新增/变化的数据
const previousState = loadPreviousState();
const currentState = fetchCurrentState();
const diff = computeDiff(previousState, currentState);

if (diff.length === 0) {
  return "无变化，跳过分析";
}

// 只有变化时才调用 AI
return analyzeChanges(diff);
```

## 四、反模式清单

| 反模式 | 问题 | 正确做法 |
|--------|------|----------|
| 用 AI 轮询 API | Token 浪费 | 脚本轮询，异常触发 AI |
| 让 AI 做数学计算 | 慢且易错 | 脚本计算，AI 解释结果 |
| 全量数据传给 AI | 上下文爆炸 | 脚本预处理，摘要给 AI |
| 每次会话重新分析 | 重复工作 | 持久化结论，增量更新 |
| AI 处理所有判断 | 延迟高 | 简单判断用规则，复杂判断用 AI |

## 五、评估指标

**健康指标**:
- 脚本化率: 脚本处理任务占比 (目标 >80%)
- Token 效率: 每任务平均 Token 消耗 (越低越好)
- 响应延迟: 端到端响应时间 (脚本层 <1s，AI 层 <5s)
- 命中率: 缓存命中比例 (目标 >60%)

## 六、迁移路径

现有任务逐步迁移到分层架构：

```
阶段 1: 识别 → 找出当前用 AI 做数据处理的流程
阶段 2: 脚本化 → 将数据处理部分写成脚本
阶段 3: 条件化 → 添加阈值判断，减少 AI 调用
阶段 4: 优化 → 添加缓存、批处理、增量更新
```

## 七、每日 Token 优化审查

> 🔄 持续改进：每天自动检查优化机会

### 7.1 审查机制

**目标**: 在保持功能不变的前提下，降低 Token 消耗

**审查频率**: 每日一次（建议凌晨或低峰时段）

**触发方式**:
- 自动：配置 cron 定时执行
- 手动：用户说 "检查token优化" 或 "审查效率"

### 7.2 检查清单

#### 检查项 1: 重复性 AI 任务
```
□ 统计过去 24h 各任务执行次数
□ 找出执行 >3 次的相似任务
□ 判断是否可脚本化
```

**示例发现**:
```markdown
| 任务 | 次数 | 建议 |
|------|------|------|
| 查询状态 | 15次 | → L1 脚本 + 缓存 |
| 格式化数据 | 8次 | → L0 脚本处理 |
```

#### 检查项 2: 高频查询优化
```
□ 识别高频查询模式
□ 检查是否已缓存
□ 评估预计算可行性
```

**优化策略**:
- 查询结果不变？→ 添加缓存
- 查询涉及计算？→ 预计算 + 定时更新
- 查询数据量大？→ 分页 + 增量加载

#### 检查项 3: 阈值决策自动化
```
□ 找出基于阈值的 AI 决策
□ 判断是否可规则化
□ 设计分层触发机制
```

**示例**:
```javascript
// 优化前: 每次都用 AI 判断
"当前值是 85，是否超过阈值 80？"

// 优化后: 脚本判断，异常才通知
if (value > 80) {
  return "⚠️ 超过阈值，需关注";
}
```

#### 检查项 4: 数据处理流程
```
□ 审查 AI 处理的数据转换任务
□ 识别纯计算/格式化操作
□ 迁移到脚本层
```

**常见可迁移任务**:
- JSON → 表格转换
- 数值计算与聚合
- 日期格式化
- 字符串处理
- 数据筛选与排序

#### 检查项 5: 增量更新机会
```
□ 检查全量数据处理任务
□ 评估增量更新可行性
□ 实现 diff-based 处理
```
