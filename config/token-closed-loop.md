## 2. 分析评估层

### 2.1 自动分析规则

| 场景 | 触发条件 | 自动动作 |

## 3. 改进执行层

### 3.1 即时改进规则

| 问题 | 即时改进 |
|------|---------|
| 回复过长 | 启用"一句话模式"直到改善 |
| 工具过多 | 下次必须说明每个工具的必要性 |
| 重复读取 | 启用缓存机制，10分钟内不重复读 |
| 历史堆积 | 自动归档30天前的文件 |

### 3.2 周期性改进任务

| 任务 | 频率 | 执行内容 |
|------|------|---------|
| 报告压缩 | 每天 | gzip 3天前的报告 |
| 笔记归档 | 每周 | 移动旧日笔记到archive |
| 核心文件精简 | 每月 | 审查SOUL.md/MEMORY.md冗余 |
| 全量清理 | 每季度 | 深度清理历史数据 |

## 4. 效果验证层

### 4.1 验证机制

**核心原则**: 绝对诚实验证 - 连续3次通过

```
改进执行
    ↓
数据验证（实际token消耗）
    ↓
通过? → 第1次 ✅
    ↓
等待后验证（间隔≥30分钟）
    ↓
通过? → 第2次 ✅
    ↓
等待后验证（间隔≥30分钟）
    ↓
通过? → 第3次 ✅
    ↓
问自己"真的吗???" → 通过 → 确认改进有效
```

### 4.2 验证指标

| 验证项 | 通过标准 |
|--------|---------|
| 回复精简 | 连续10次回复平均≤1000 tokens |
| 工具优化 | 连续10次回复平均≤3个工具 |
| 文件读取 | 单次会话不重复读取同一文件 |
| 日耗控制 | 连续3天≤50k tokens |

## 5. 反馈调整层

### 5.1 自动调整规则

| 反馈 | 调整动作 |
|------|---------|
| 验证失败 | 回到改进执行层，尝试其他方法 |
| 验证通过 | 固化规则，写入AGENTS.md |
| 新问题 | 加入监控指标，开始新一轮闭环 |

### 5.2 规则固化

验证通过的改进，必须写入：
- `AGENTS.md` - 操作规范
- `SOUL.md` - 核心原则更新
- `TOOLS.md` - 工具使用优化
