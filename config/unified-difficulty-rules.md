# 统一模型分级系统
# 所有模型根据任务复杂度自动调整thinking模式

## 难度等级定义（L1-L5）

### L1 极简 - all models: off
**触发词**：
- 你好、在吗、状态怎么样、当前
- 几点、什么时间、今天日期
- 确认、好的、取消、是、否
- 简单一词回复

**任务特征**：
- 输入长度 < 10字
- 无代码块
- 无复杂逻辑要求

### L2 简单 - free: off/concise, k2p5: concise
**触发词**：
- 语法、报错、错误怎么修
- 示例、怎么写、简单问题
- 配置、基本概念

**任务特征**：
- 代码行数 < 10行
- 单文件修改
- 解释简单概念

**Thinking配置**：
- ds: off（默认）
- kimi: concise
- glm: concise
- k2p5: concise

### L3 中等 - free: concise/on, k2p5: on
**触发词**：
- 函数、模块、实现、接口
- 测试、优化、重构
- 调试（非疑难）

**任务特征**：
- 代码行数 10-50行
- 2-3个文件关联
- 需要理解上下文

**Thinking配置**：
- ds: concise
- kimi: concise
- glm: on
- k2p5: on

### L4 困难 - all models: on
**触发词**：
- 架构、设计、策略
- 复杂算法、系统重构
- 分布式、并发、性能
- 多系统、集成、数据流

**任务特征**：
- 代码行数 50-200行
- 跨模块/服务设计
- 技术选型决策

**Thinking配置**：
- all models: on

### L5 极难 - k2p5: stream, others: on
**触发词**：
- 从零设计、核心架构
- 大规模、高可用、容灾
- 疑难bug、深度优化
- 瓶颈、性能关键路径

**任务特征**：
- 代码行数 > 200行
- 多技术栈整合
- 性能/安全关键

**Thinking配置**：
- ds/kimi/glm: on（能力上限）
- k2p5: stream（过程透明）

## 模型-难度映射表

| 难度 | ds | kimi | glm | k2p5 |
|------|----| ----| ----| ----|
| L1 极简 | off | off | off | off |
| L2 简单 | off | concise | concise | concise |
| L3 中等 | concise | concise | on | on |
| L4 困难 | on | on | on | on |
| L5 极难 | on | on | on | stream |

## 权重因素

### 长度权重
- 消息 > 1000字 → +1级
- 代码块 > 100行 → +1级

### 上下文权重
- "生产环境" → +1级
- "紧急/线上问题" → +1级
- "架构评审" → +1级

### 降级权重
- "简单问题" → -1级
- "快速看一下" → -2级（最低L1）

## 辅助规则

### 模型能力上限
- ds: 最大L4（无stream）
- kimi: 最大L4（无stream）
- glm: 最大L4（无stream）
- k2p5: 可达L5（stream）

### 特殊场景
- 图片分析 → kimi, 起步L3
- 长文档 → kimi, 起步L3
- 中文优化 → glm, 起步L2
- 代码开发 → k2p5, 根据难度动态
