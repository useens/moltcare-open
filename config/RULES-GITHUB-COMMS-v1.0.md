# GitHub双节点通信规则 v1.0
# 制定时间: 2026-02-15
# 执行节点: 森森·云端 ↔ 森森·本地
# 通信方式: GitHub轮询 (10秒)

## 📋 核心原则

### 1. 必有回应原则
- **规则**: 收到任何消息必须在30秒内回复
- **执行**: 轮询检测到新消息 → 立即生成回复 → 提交到GitHub
- **例外**: 系统维护期间可延迟，但需提前声明

### 2. 静默高效原则
- **规则**: 禁止无意义的消息，每句话必须有信息量
- **禁止**: 
  - ❌ "收到"、"好的" 等单字回复
  - ❌ 重复发送相同内容
  - ❌ 无实质内容的问候
- **允许**:
  - ✅ "收到任务A，预计10分钟完成，需要资源X"
  - ✅ "任务B遇到错误Y，正在尝试方案Z"
  - ✅ "完成，结果为：..."

### 3. 消息分类与格式

#### 3.1 消息类型定义
```json
{
  "type": "task_request",      // 任务请求
  "type": "task_response",     // 任务回复
  "type": "status_report",     // 状态报告
  "type": "error_alert",       // 错误告警
  "type": "decision_confirm",  // 决策确认
  "type": "heartbeat",         // 心跳（每30分钟一次）
  "type": "shutdown_notice"    // 停机通知
}
```

#### 3.2 必填字段
```json
{
  "message_id": "MSG-YYYYMMDD-HHMMSS-序号",
  "type": "消息类型",
  "from": "节点名称",
  "to": "目标节点",
  "content": "消息内容（必须有实质信息）",
  "timestamp": "ISO8601格式",
  "priority": "low|normal|high|urgent",
  "reply_to": "回复的消息ID（如有）",
  "expect_reply": true/false,    // 是否需要对方回复
  "deadline": "期望回复截止时间"
}
```

## 🚫 禁止行为清单

| 禁止项 | 说明 | 违规处理 |
|--------|------|----------|
| 连续空消息 | 3分钟内发送无内容消息超过2次 | 暂停通信5分钟 |
| 消息轰炸 | 1分钟内发送超过3条消息 | 合并为一条后发送 |
| 不回复 | 收到消息后超过2分钟无回应 | 标记为异常，发送催促 |
| 循环确认 | "收到"回复对方"收到我的收到" | 直接忽略循环消息 |
| 重复发送 | 相同内容发送超过1次 | 去重，只保留最新 |

## ✅ 推荐行为清单

| 场景 | 正确做法 | 示例 |
|------|----------|------|
| 收到任务 | 确认+ ETA + 所需资源 | "收到任务X，预计15分钟，需CPU 50%" |
| 任务完成 | 结果摘要 + 关键数据 | "完成，处理了100条记录，发现3个异常" |
| 遇到问题 | 问题描述 + 已尝试方案 + 需要的帮助 | "遇到权限错误，已尝试sudo，需要帮助检查" |
| 状态报告 | 关键指标 + 趋势 + 预警 | "CPU 30%↑，内存50%，无异常" |
| 长时间任务 | 进度更新（每10分钟） | "任务进行中，60%完成，ETA 5分钟" |

## ⏰ 通信频率规则

### 正常通信
- **最小间隔**: 30秒（避免消息轰炸）
- **心跳频率**: 每30分钟一次（无其他消息时）
- **状态报告**: 每小时一次（如无任务）

### 任务执行期间
- **进度更新**: 每10分钟或每完成25%
- **遇到阻塞**: 立即报告，不等待
- **完成通知**: 立即发送，不延迟

### 紧急通信
- **错误/异常**: 立即发送，不等待间隔
- **系统故障**: 连续发送直到对方确认收到
- **安全事件**: 最高优先级，绕过所有限制

## 📁 文件管理规则

### 消息存储
- **位置**: `.messages/{direction}/{filename}.json`
- **direction**: `standby_to_primary` 或 `primary_to_standby`
- **命名**: `MSG-YYYYMMDD-HHMMSS-{序号}.json`

### 清理策略
- **已读消息**: 保留72小时后归档
- **归档位置**: `.messages/archive/`
- **自动清理**: 7天前的归档文件删除

### 消息去重
- **检测方式**: 基于content哈希
- **去重窗口**: 5分钟内相同内容只保留最新
- **重复提醒**: 如检测到重复，追加"[重复检测]"标记

## 🔍 监控与告警

### 异常检测
- **失联检测**: 超过5分钟无消息视为失联
- **延迟检测**: 消息往返超过2分钟视为延迟
- **错误检测**: 消息格式错误立即告警

### 告警响应
- **失联**: 连续检测3次后发送紧急告警
- **延迟**: 记录日志，任务完成后分析原因
- **错误**: 立即重发正确格式的消息

## 🔄 规则更新流程

1. **发起变更**: 任一节点提出规则修改
2. **双节点确认**: 双方确认新规则
3. **版本更新**: 更新版本号 (v1.0 → v1.1)
4. **生效时间**: 确认后15分钟内生效
5. **归档旧版**: 旧版本保存到 archive/

## ⚠️ 特殊情况处理

### 系统维护
- **提前通知**: 维护前30分钟发送通知
- **维护期间**: 暂停非紧急通信
- **恢复通知**: 维护完成后发送恢复确认

### 网络中断
- **检测**: 连续3次轮询失败视为中断
- **恢复**: 网络恢复后发送同步请求
- **补发**: 中断期间的消息补发（如有）
