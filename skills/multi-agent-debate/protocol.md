# Multi-Agent 实时辩论协议 v1.0

> 适用于复杂技术决策，需要多方专家协作论证的场景

---

## 📋 协议概述

**目标**：模拟 Grok 4.20 的多专家实时讨论机制，通过3轮渐进式辩论达成共识

**角色定义**：
- 🔍 **Harper** - 研究/数据专家：负责技术调研、性能数据、最佳实践
- 🧠 **Benjamin** - 架构/安全专家：负责整体设计、安全模型、可扩展性
- 💻 **Lucas** - 实现/工程专家：负责代码可行性、工期评估、潜在坑点
- 👑 **Grok (队长)** - 整合专家意见，做出最终裁决

---

## 🔄 三轮辩论流程

### Round 1: 独立分析（并行，~1.5分钟）
**目标**：建立初始立场

**每个专家**：
1. 独立分析问题，不考虑他人观点
2. 输出：技术分析/架构设计/实现规划
3. 预判：预计会被其他专家质疑的点
4. 坚持：自己的核心立场

**输出格式**：
```markdown
## [时间戳] 专家名 - Round 1

### 我的分析
...

### 预计的质疑点
- @Benjamin: 可能会说...
- @Lucas: 可能会质疑...

### 我的坚定立场
- 必须坚持的点...
```

**状态存储**：`/shared/round-1/{harper,benjamin,lucas}.md`

---

### Round 2: 回应与质疑（并行，~1.5分钟）
**目标**：互相质疑，暴露问题

**每个专家**：
1. 读取其他两位 Round 1 的输出
2. 分析他人观点，找出：
   - 同意的点（给出理由）
   - 质疑的点（具体问题和数据/原则支撑）
   - 需要补充的信息
3. 提出具体质疑，要求对方回应

**输出格式**：
```markdown
## [时间戳] 专家名 - Round 2

### 我同意的点
- @Benjamin: ...（理由）
- @Lucas: ...（理由）

### 我的质疑
- @Benjamin: ...（具体问题）
  我的数据/原则：...
  建议：...

- @Lucas: ...（具体问题）
  我的数据/原则：...
  建议：...

### 我的回应
- 针对质疑我的观点...

### 我坚持的观点
- ...
```

**状态存储**：`/shared/round-2/{harper,benjamin,lucas}.md`

---

### Round 3: 达成共识（并行，~1.5分钟）
**目标**：基于辩论做出妥协和最终决策

**每个专家**：
1. 读取 Round 2 的所有辩论
2. 做出妥协：哪些点可以让步？
3. 坚持底线：哪些点必须坚持？
4. 最终立场：基于辩论调整后的方案

**输出格式**：
```markdown
## [时间戳] 专家名 - Round 3 (最终立场)

### 我妥协的点
1. ...（妥协理由）
2. ...

### 我坚持的点
1. ...（为什么必须坚持）
2. ...

### 我的最终推荐
**技术栈**: ...
**工期**: ...
**理由**: ...
```

**状态存储**：`/shared/round-3/{harper,benjamin,lucas}.md`

---

## 👑 队长裁决（Grok）

**任务**：
1. 读取所有三轮的输出
2. 整合各方妥协和坚持点
3. 做出最终技术决策
4. 生成最终共识报告

**输出**：
- 技术栈共识
- 架构决策
- 工期评估
- 各方妥协总结

## 🎯 适用场景

✅ **适合使用**：
- 技术选型决策（框架/数据库/缓存）
- 架构设计评审
- 复杂功能实现方案
- 性能优化策略
- 安全模型设计

❌ **不适合使用**：
- 简单任务（单专家即可）
- 紧急任务（需要4-6分钟）
- 高度主观偏好问题
- 缺乏明确评判标准的问题
