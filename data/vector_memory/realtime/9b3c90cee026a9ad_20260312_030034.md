## 二、L3触发条件

### 2.1 强制触发L3的场景

| 场景 | 说明 | 示例 |
|------|------|------|
| **Signal 9-10级别问题** | 严重缺陷或高价值机会 | 进化机制完全失效、资源利用率<20% |
| **架构级改进** | 影响系统设计的变化 | 重写任务调度器、新建核心服务 |
| **重大决策** | 高影响选择 | 资源分配策略调整、安全边界变更 |
| **跨系统协调** | 多组件联动 | 升级守护进程与监控系统整合 |

## 三、方案区分格式

### 3.1 L2建议格式

```markdown
**L2建议**: 增加资源监控频率
- 当前: 每6小时检查一次
- 建议: 每2小时检查一次
- 预期效果: 更快发现问题
```

### 3.2 L3方案格式

```markdown
🔥 **L3方案**: 重构资源管理架构

**问题本质**: 资源利用低不是监控不足，而是激励机制缺失

**架构级解决方案**:
1. 引入资源利用效率指标（KPI）
2. 建立资源利用与任务优先级联动机制
3. 设计自适应资源分配算法

**实施路径**:
- Phase 1: 基础设施（1周）
- Phase 2: 算法开发（2周）
- Phase 3: 全面对接（1周）

**风险控制**: 需确保自适应不会导致资源争抢
```

## 五、环境变量配置

### 5.1 systemd服务新增环境变量

```ini
Environment="THINKING_MODE=adaptive"  # low/medium/high/adaptive
Environment="L3_TRIGGER_SIGNAL=9"     # Signal阈值触发L3
Environment="DEFAULT_THINKING=medium" # 默认thinking模式
```

### 5.2 脚本读取方式

```python
import os

# 读取当前thinking模式
thinking_mode = os.environ.get('CURRENT_THINKING_MODE', 'medium')

# 判断是否使用L3
use_l3 = thinking_mode == 'high' or signal_level >= 9
```
