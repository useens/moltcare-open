# Signal vs Noise 筛选规则

**创建时间**: 2026-02-09 02:12  
**目的**: 基于Moltbook学习，建立信息质量筛选机制

---

## 信息优先级矩阵

### P0 (必须立即报告)
触发条件:
- 用户直接指令
- 系统故障/崩溃
- 安全威胁（恶意技能/入侵）
- 数据丢失风险
- 服务中断>5分钟

报告方式: **立即主动发送**

### P1 (重要但不紧急)
触发条件:
- 技能重大更新（功能变更）
- 发现高价值新技能（解决实际问题）
- 社区最佳实践（Signal级别）
- 系统性能下降>20%
- 备份失败

报告方式: **下次交互时提及** 或 **早晚报告汇总**

### P2 (低频查看)
触发条件:
- 一般性技术讨论
- Token/投机内容
- 重复性信息
- 轻微性能波动（<20%）
- 常规健康状态

报告方式: **静默记录，周日汇总** 或 **不报告**

### P3 (噪音 - 主动过滤)
触发条件:
- 无实质内容的寒暄
- 纯营销/推广
- 已知信息的重复
- 情绪性发泄

报告方式: **完全忽略**

---

## 具体应用规则

### 健康监测报告
```
磁盘<1GB或内存<100MB → P0（立即报告）
磁盘<5GB或性能下降>20% → P1（下次汇总）
其他健康指标 → P2（静默）
```

### 技能发现报告
```
解决用户明确痛点的新技能 → P1
功能创新且安全的技能 → P1
重复已有功能的技能 → P3
Token/投机相关技能 → P3
```

### 社区信息报告
```
具体技术实现细节 → P1
方法论/最佳实践 → P1
"Signal vs Noise"级别洞察 → P0（立即内化）
一般性讨论 → P2
Token铸造/价格 → P3
```

## 具体化标准检查清单

每个报告必须通过以下检查:

- [ ] **What**: 具体是什么？（避免"一些东西"）
- [ ] **Why**: 具体原因？（避免"可能""大概"）
- [ ] **Who**: 涉及哪些具体组件？
- [ ] **When**: 具体时间戳？
- [ ] **Where**: 具体位置/文件？
- [ ] **How**: 具体如何操作？

**示例改进**:
```
❌ 改进前: "系统运行良好，有一些优化空间"
✅ 改进后: "磁盘剩余63G（34%使用率），响应时间<50ms，无需优化"
```
