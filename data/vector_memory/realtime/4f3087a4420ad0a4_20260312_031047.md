## 🎯 核心论点

### 1. 模型能力分层 (关键洞察)

| 层级 | 模型 | 能力 | 适用场景 | 成本 |
|------|------|------|----------|------|
| **T0 (大学生)** | Claude Opus 4.6, GPT 5.3 CodeX | 逻辑严密、复杂代码、系统架构、自主查文档测试 | 基础设施搭建、源码修改、复杂二次开发 | 贵 |
| **T1.5 (小学生)** | Minimax 2.5, GLM-5 | 简单任务、速度快 | 日常执行、已定型的任务流 | 便宜 |

**核心误区**: 用 T1.5 模型干 T0 的活 → 永远卡在Bug里

### 2. 双模型架构 (解决方案)

```
┌─────────────────────────────────────────┐
│           双模型架构                      │
├─────────────────────────────────────────┤
│                                         │
│   Antigravity (Brain)                   │
│   ├── Opus 4.6 / GPT 5.3 CodeX         │
│   ├── 搭建基础设施                       │
│   ├── 修改源码/配置                      │
│   ├── 开发 Skills/Tools                 │
│   └── 解决复杂问题                       │
│           ↓ (固化后)                     │
│   OpenClaw (Hand)                       │
│   ├── Minimax M2.5 / GLM-5              │
│   ├── 执行日常任务                       │
│   └── 调用已配置好的工具                  │
│                                         │
└─────────────────────────────────────────┘
```

**类比**: 不要试图让小学生解微积分，也不要用大炮打蚊子

### 3. Vibe Coding 降维打击

**关键转变**: 把 OpenClaw 当作 **Project** 而不是 **服务**

- ❌ 错误: 在 OpenClaw 对话框里让它修改自己
- ✅ 正确: 用 Cursor/Codex/Antigravity 打开 OpenClaw 项目文件夹直接改代码

**实战流程**:
1. **基础设施阶段** (Opus) - 写脚本、配环境、解决边缘情况
2. **固化沉淀** - 代码/配置保存，成为基础设施
3. **日常执行** (Minimax) - 低成本运行已定型的任务流

## 🔥 实战案例解析

### 案例: 本地浏览器智能体

**问题**: OpenClaw 自带浏览器是隔离环境，每次需要登录

**解决方案**:
1. **Opus 阶段**: 写 `start-chrome-debug.sh`
   - 远程调试模式启动 Chrome
   - 复用本地 Cookie
   - 解决端口冲突
   - 锁文件清理
   - User Data 目录复用

2. **Minimax 阶段**: 执行日常任务
   - 打开已登录的浏览器
   - 抓取推特推荐页
   - 生成飞书文档

**结果**: 几分钱 Token 成本，完成复杂操作

## 💡 对森森的启示

### 1. 架构层面

当前森森的问题:
- 所有任务都用同一模型 (kimi-coding/k2p5)
- 复杂开发和日常执行没有区分
- 在对话中修改配置/代码

**改进方向**:
```
Development Mode (高能力模型)
├── 修改 AGENTS.md / SOUL.md
├── 开发新 Skills
├── 复杂系统重构
└── 解决棘手Bug

Production Mode (低成本模型)
├── 心跳检查
├── 日常监控
├── 执行已定型的任务
└── 简单响应
```

### 2. 工作流层面

**应该使用双模型的情况**:
- ✅ 修改 OpenClaw/森森源码或配置
- ✅ 接入本地服务（浏览器、数据库、API）
- ✅ 开发自定义 Tool 或 Skill
- ✅ 解决复杂 Bug
- ✅ 多步骤自动化任务

**单模型足够的情况**:
- ❌ 纯聊天、问问题
- ❌ 简单任务（查天气、设提醒）
- ❌ 开箱即用的功能已满足
