## 🔴 一级问题 (必须立即处理)

### 1. 脚本数量严重失控

**数据**: 230个脚本 (scripts目录) + 根目录散落脚本

**问题分析**:
- 脚本数量是健康规模的 **5-10倍**
- 功能重叠度估计: **60%+**
- 实际高频使用: 估计 **<20个**

**真实案例**:
```
hyper-evolution-engine.py → 废弃在.trash
hyper-evolution-engine-v11.py → 废弃
hyper-evolution-engine-v12.py → 废弃
hyper-evolution-engine-v20.py → 废弃
hyper-evolution-engine-v21.py → 废弃
hyper-evolution-engine-v30.py → 废弃
hyper-evolution-engine-v35.py → 废弃
hyper-evolution-engine-v40.py → 废弃
hyper-evolution-engine-v46.py → 当前使用
```

**浪费评估**: 仅这一个功能就产生了 **8个废弃版本**

### 2. 重复脚本对 (100%重复)

| 脚本A | 脚本B | 位置 |
|-------|-------|------|
| `minimal-reporter-v10.py` | `minimal_reporter_v10.py` | scripts/ |
| `token-optimizer-v10.py` | `token_optimizer_v10.py` | scripts/ |
| `collect-web-intel.py` | `collect-web-intel-fast.py` | scripts/ |
| `collect-web-intel-hyper.py` | 以上两者 | scripts/ |

**问题**: 命名不规范导致同一脚本存在多个副本

## 🟠 二级问题 (需要优化)

### 5. 日志系统混乱

**发现**:
- logs/目录日志: cron-health.log (15K), forced-git-sync.log (150K)
- data/目录也有日志: token-usage.log (32K)
- 记忆系统也有日志: logs/memory/consolidation.log (29K)

**问题**: 日志分散在3个不同位置，无统一策略

### 6. Cron任务配置混乱

**现状**:
```bash
# 当前只有1个cron任务
crontab -l:
*/5 * * * * /usr/local/bin/sensen-chat-healthcheck.sh

# 但配置脚本有多个:
scripts/setup-cron.sh          # v5健康检查
tools/setup-hyper-cron.sh      # 超进化模式
tools/daily-web-intel-collection.py  # 日常情报
```

**问题**: 多个配置脚本争夺cron控制权

### 7. 功能重叠: Moltbook提取器

**发现**:
```
extract_moltbook.py
extract_moltbook_posts.py
moltbook-detail-extract.py
moltbook-detail-extract-v2.py
moltbook-quick-extract.py
moltbook-super-extractor.py
moltbook-unified.py        ← 当前统一版本
moltbook-unified-scan.py
```

**问题**: 8个提取器最终统一为1个，但旧版本仍在

### 8. Token使用记录异常

**分析 token-usage.log**:
```
# 发现模式: 重复固定的token计数
{"operation": "情报收集", "tokens_in": 100, "tokens_out": 50, "total": 150}
{"operation": "任务执行", "tokens_in": 200, "tokens_out": 100, "total": 300}
```

**问题**: 
- 所有记录都是固定值，**数据不真实**
- 存在**虚假Token追踪**现象

## ⚠️ 风险评估

### 精简风险 (中等)
- 误删仍在使用的脚本
- 破坏隐藏依赖关系
- 影响自动化流程

### 缓解措施
1. 所有操作先移动到.trash，保留7天
2. 操作前记录git commit
3. 分阶段执行，每阶段验证
4. 核心功能灰度测试
