## 📊 核心改进

### 1. 双节点架构保障

| 场景 | 进化能力 | 保障机制 |
|------|----------|----------|
| 双节点正常 | 100% | VM执行任务，主节点监控+备份 |
| 单节点运行 | 100% | 所有进化任务在主节点继续执行 |
| VM恢复后 | 100% | 自动同步，无数据丢失 |

**VM角色定位**:
- 任务执行节点（计算密集型任务）
- 备份待命（可从主节点仓库恢复）
- 不独立备份到GitHub（成本优化）

### 2. 自主进化系统 v4.2 完整配置

**13个定时任务**:

| 任务ID | 名称 | 周期 | 执行时间 |
|--------|------|------|----------|
| `health-check-2h` | 健康检查 | 每2小时 | 持续 |
| `health-monitor-v5` | 自我诊断 | 每10分钟 | 持续 |
| `vm-status-monitor` | VM状态监控 | 每分钟 | 持续 |
| `evolution-light-4h` | 轻量进化 | 每4小时 | 00:00, 04:00, 08:00... |
| `evolution-full-8h` | **全量进化** | **每8小时** | **03:00, 11:00, 19:00** |
| `night-evolution-1` | 夜间进化阶段1 | 每天 | 23:00 |
| `night-evolution-2` | **夜间进化阶段2** | **每天** | **02:00** |
| `night-evolution-3` | **夜间进化阶段3** | **每天** | **05:00** |
| `moltbook-community` | Moltbook社区 | 每天 | 06:00 |
| `web-extractor-intel` | **网页情报收集** | **每天** | **04:00** |
| `github-backup-sync` | GitHub备份 | 每30分钟 | 持续 |
| `weekly-cleanup` | 每周清理 | 每周日 | 03:00 |
| `monthly-deep-cleanup` | **月度深度清理** | **每月1号** | **00:00** |

| 项目 | 原配置 | v4.2配置 |

## 📝 经验教训

**本次部署过程中的关键修复**:

1. **SSH密钥路径问题**: 监控脚本使用`/tmp/linlin_cloud_key`而实际认证使用`/root/.ssh/id_ed25519`，导致VM状态检测失败
2. **Token多次暴露**: GitHub Token在对话中暴露3次，已全部撤销并重新生成
3. **进化任务遗漏**: 原配置缺少网页情报收集和月度深度清理任务
4. **夜间进化不完整**: 只配置了阶段1，缺少阶段2（知识内化）和阶段3（系统优化）

**已归档到**: `MEMORY.md` 永久记忆
