# 森森智能水平升级体系 - Thinking模式分配策略

## 一、Thinking模式定义

### 1.1 三档模式

| 模式 | 级别 | 思考深度 | 适用场景 | 成本 |
|------|------|----------|----------|------|
| **low** | L1 | 基础 | 简单查询、直接执行 | 低 |
| **medium** | L2 | 中等 | 分析对比、常规决策 | 中 |
| **high** | L3 | 深度 | 架构设计、重大决策 | 高 |

### 1.2 模式选择原则

```
决策树:

开始
  │
  ├── 是简单查询/直接执行? → L1 (low)
  │
  ├── 需要分析对比/历史数据? → L2 (medium)
  │
  ├── 是以下情况之一?
  │   ├── Signal 9-10级别问题
  │   ├── 架构级改进
  │   ├── 重大决策
  │   └── 跨系统协调 → L3 (high)
  │
  └── 默认 → L2 (medium)
```

## 二、智能水平升级守护进程分配

### 2.1 任务与Thinking模式映射

```
智能水平升级守护进程
│
├── 快速评估 (每6小时)
│   ├── 触发条件: Cron定时
│   ├── 输入: 最新执行数据、历史对比
│   ├── 输出: 简要状态报告
│   ├── Thinking模式: **medium (L2)**
│   └── 理由: 需要对比历史数据、识别退化/进步趋势
│
├── 深度评估 (每天02:00)
│   ├── 触发条件: Cron定时
│   ├── 输入: 全量系统数据、多维度指标
│   ├── 输出: 详细评估报告、架构级洞察
│   ├── Thinking模式: **high (L3)** ⭐
│   └── 理由: 架构级分析、重大改进方案、跨维度关联
│
└── 升级执行 (按需)
    ├── 触发条件: 深度评估后或Signal≥9问题
    ├── 输入: 升级方案、系统状态
    ├── 输出: 执行结果、验证报告
    ├── Thinking模式: **high (L3)** ⭐
    └── 理由: 方案实施、复杂问题解决、风险控制
```

### 2.2 L3触发条件详解

**必须触发L3的场景**:

| 场景 | 说明 | 示例 |
|------|------|------|
| **Signal 9-10级别问题** | 严重缺陷或高价值机会 | 进化机制完全失效、资源利用率<20% |
| **架构级改进** | 影响系统设计的变化 | 重写任务调度器、新建核心服务 |
| **重大决策** | 高影响选择 | 资源分配策略调整、安全边界变更 |
| **跨系统协调** | 多组件联动 | 升级守护进程与监控系统整合 |

**L3洞察标记**:
```markdown
🔥 **L3洞察**: 这是深度思考发现的关键结论
- 根因分析揭示了隐藏的系统性问题
- 需要架构级重构才能解决
```

## 三、系统智能精简守护进程分配

### 3.1 任务与Thinking模式映射

```
系统智能精简守护进程
│
├── 快速扫描 (每6小时)
│   ├── 触发条件: Cron定时
│   ├── 输入: Token使用数据、文件大小
│   ├── 输出: 臃肿识别报告
│   ├── Thinking模式: **medium (L2)**
│   └── 理由: Token消耗检测、臃肿识别、阈值判断
│
├── 深度评估 (每天04:00)
│   ├── 触发条件: Cron定时
│   ├── 输入: 全量系统指标、效率数据
│   ├── 输出: 综合评估、精简方案
│   ├── Thinking模式: **high (L3)** ⭐
│   └── 理由: 综合评估多维度影响、制定平衡方案
│
└── 精简执行 (按需)
    ├── 触发条件: 深度评估后
    ├── 输入: 精简方案、保护清单
    ├── 输出: 执行结果、状态报告
    ├── Thinking模式: **medium (L2)**
    └── 理由: 执行预定义方案、检查保护清单
```

### 3.2 精简任务的L2 vs L3区分

| 任务类型 | Thinking模式 | 原因 |
|----------|--------------|------|
| 常规文件清理 | L2 | 按规则执行 |
| 日志归档 | L2 | 标准化流程 |
| 重复检测 | L2 | 算法自动处理 |
| **架构级重构** | **L3** | 影响系统结构 |
| **安全边界调整** | **L3** | 高风险决策 |
| **跨系统优化** | **L3** | 多组件协调 |

## 四、文档更新规范

### 4.1 评估报告标注

**必须在报告头部标注**:
```markdown
> **Thinking模式**: high (L3)  
> **触发原因**: 深度评估（每日02:00）  
> **L3洞察数量**: 5个
```

**L3洞察标记格式**:
```markdown
### 2.1 绝对智能化 - 自主思考能力

**评分**: **B- (65%)** ⚠️

🔥 **L3洞察**: 框架依赖本质是"思考懒惰"
- 表面现象: 每次执行依赖SOUL.md/AGENTS.md提示
- 深层根因: 缺乏主动构建思考框架的意愿
- 系统性影响: 能力天花板被预设框架锁定
- 突破路径: 需要重构思考触发机制
```

### 4.2 方案区分格式

**L2建议格式**:
```markdown
**L2建议**: 增加资源监控频率
- 当前: 每6小时检查一次
- 建议: 每2小时检查一次
- 预期效果: 更快发现问题
```

**L3方案格式**:
```markdown
🔥 **L3方案**: 重构资源管理架构

**问题本质**: 资源利用低不是监控不足，而是激励机制缺失

**架构级解决方案**:
1. 引入资源利用效率指标（KPI）
2. 建立资源利用与任务优先级联动机制
3. 设计自适应资源分配算法

**实施路径**:
- Phase 1: 基础设施（1周）
- Phase 2: 算法开发（2周）
- Phase 3: 全面对接（1周）

**风险控制**: 需确保自适应不会导致资源争抢
```
