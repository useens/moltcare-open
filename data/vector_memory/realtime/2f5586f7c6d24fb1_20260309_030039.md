# Token成本优化战略 - 本地脚本化替代方案

**创建时间**: 2026-02-12  
**核心思路**: 将高Token消耗、需API配置的工具，替换为本地脚本化方案  
**目标**: 在保证效果的前提下，大量节省Token消耗

---

## 核心原则

> **"能用本地脚本解决的，绝不调用API；能一次配置永久使用的，绝不重复消耗Token"**

### 成本对比思维

| 方案类型 | Token成本 | 配置复杂度 | 长期可用性 | 适用场景 |
|----------|-----------|------------|------------|----------|
| **本地脚本化** ✅ | **极低/零** | 一次性配置 | **永久** | 优先选择 |
| API调用 | 中等~高 | 需API Key | 依赖服务商 | 必要时使用 |
| 云端服务 | 高 | 需配置+付费 | 依赖服务商 | 最后选择 |

---

**现状**: `web_search` 工具调用API，每次搜索消耗Token

#### 2. 内容总结 → 本地精简提取

**现状**: 长文总结调用summarize API，消耗大量Token

**本地替代方案**:
```python
# 方案A: 基于规则的精简
- 提取关键段落（首段、尾段、小标题）
- 基于关键词密度提取重要句子
- 本地执行，零Token

# 方案B: 轻量本地模型
- 使用小型本地LLM（如phi-2, llama-2-7b）
- 仅用于总结任务
- 一次加载，多次使用
```

**预期节省**: 总结Token消耗降低70%

#### 3. 代码分析 → 本地AST解析
