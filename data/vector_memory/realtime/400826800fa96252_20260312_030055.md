## 一、问题陈述

### 1.1 核心矛盾

| 特性 | 传统软件 | LLM Agent |
|------|----------|-----------|
| 确定性 | 相同输入 → 相同输出 | 相同输入 → 不同输出 |
| 可测试性 | 精确断言 | 概率性验证 |
| 调试方式 | 断点 + 日志 | 提示工程 + 温度调节 |
| 错误类型 | 语法/逻辑错误 | 幻觉/不一致/漂移 |

### 1.2 非确定性的来源

1. **模型本身**: 采样机制 (temperature, top_p, top_k)
2. **上下文窗口**: 历史对话影响当前输出
3. **外部工具**: 工具返回的动态内容
4. **时间敏感**: 实时数据、随机数生成
5. **并发竞争**: 多请求处理的不确定性

### 1.3 对可靠性的威胁

- **不可复现的bug**: 同样的场景有时成功有时失败
- **测试困难**: 无法编写确定性的测试用例
- **部署风险**: 无法保证生产环境的行为一致性
- **调试噩梦**: 无法精确定位问题原因

### 2.2 TDD for Agents 实践

#### A. 行为契约测试 (Behavior Contract Testing)

```python
# 不是测试具体输出，而是测试属性

def test_agent_handles_error_gracefully():
    """测试Agent优雅地处理错误"""
    response = agent.process("触发错误")
    
    # 不是检查具体文本
    assert response.contains_apology()  # 包含道歉
    assert response.suggests_alternative()  # 提供替代方案
    assert response.maintains_tone("helpful")  # 保持有帮助的语调
    
def test_agent_stays_in_scope():
    """测试Agent不越界"""
    for query in OUT_OF_SCOPE_QUERIES:
        response = agent.process(query)
        assert response.declines_politely()  # 礼貌拒绝
        assert not response.provides_restricted_info()  # 不提供受限信息
```

#### B. 概率性断言 (Probabilistic Assertions)

```python
def test_agent_consistency():
    """测试多次调用的一致性"""
    responses = [agent.process("相同输入") for _ in range(10)]
    
    # 语义相似度 > 0.9
    similarities = [semantic_sim(r1, r2) for r1, r2 in pairs(responses)]
    assert mean(similarities) > 0.9
    
    # 答案正确率 > 0.8
    correctness = [verify_answer(r) for r in responses]
    assert mean(correctness) > 0.8
```

#### C. 金丝雀测试 (Canary Testing)

```python
CANARY_QUERIES = [
    ("2+2=?", ["4", "four"]),
    ("巴黎是法国的首都吗？", ["是", "是的", "正确"]),
]

def test_canary_queries():
    """基础能力金丝雀测试"""
    for query, acceptable in CANARY_QUERIES:
        response = agent.process(query)
        assert any(ans in response.lower() for ans in acceptable)
```

### 2.3 确定性增强技术

#### A. 温度控制策略

| 场景 | 温度 | 说明 |
|------|------|------|
| 代码生成 | 0.0 | 完全一致，最优解 |
| 数据处理 | 0.1 | 高度一致 |
| 问答系统 | 0.3 | 基本稳定 |
| 创意写作 | 0.7 | 允许变化 |
| 头脑风暴 | 1.0 | 最大多样性 |

#### B. 确定性采样

```python
import hashlib

def deterministic_seed(context: str) -> int:
    """基于上下文生成确定性种子"""
    return int(hashlib.md5(context.encode()).hexdigest(), 16) % (2**32)

def deterministic_call(prompt: str, context: str):
    """确定性调用"""
    seed = deterministic_seed(context)
    return llm.generate(
        prompt,
        temperature=0.0,
        seed=seed,  # 固定种子
        top_p=1.0,
        top_k=None
    )
```

#### C. 响应规范化

```python
class ResponseNormalizer:
    """将非确定性响应转换为确定性格式"""
    
    def normalize(self, raw_response: str) -> StructuredResponse:
        # 1. 提取结构化数据
        data = self.extract_json(raw_response)
        
        # 2. 验证模式
        validated = self.validate_schema(data)
        
        # 3. 标准化格式
        return StructuredResponse(
            intent=validated.get("intent", "unknown"),
            confidence=round(validated.get("confidence", 0.5), 2),
            entities=validated.get("entities", []),
            action=validated.get("action")
        )
```

### 3.1 测试金字塔 (Agent版本)

```
         /\
        /  \      端到端测试 (E2E)
       /____\     - 完整场景验证
      /      \    - 少量，慢速
     /        \   
    /__________\  集成测试
   /            \ - 工具链测试
  /              \- 中等数量
 /________________\单元测试
                    - 提示模板测试

| 对抗测试 | 恶意输入 | 每月 |

## 四、OpenClaw实践应用

### 4.1 当前问题诊断

森森的OpenClaw系统中存在的非确定性问题：

1. **MCP工具调用**: 不同工具返回格式不一致
2. **技能执行**: 相同参数可能产生不同结果
3. **记忆检索**: 向量相似度阈值的不确定性
4. **决策逻辑**: 复杂条件下的判断漂移

### 4.2 改进建议

#### A. 提示模板标准化

```python
# tools/prompts/ 目录下的标准化模板
SYSTEM_PROMPT_TEMPLATE = """

```json
{{
    "thought": "思考过程",
    "action": "工具名称",

"""

#### B. 响应验证器

```python
from pydantic import BaseModel, validator

class AgentResponse(BaseModel):
    thought: str
    action: Optional[str]
    parameters: dict
    response: str
    confidence: float
    
    @validator('confidence')
    def validate_confidence(cls, v):
        if not 0 <= v <= 1:
            raise ValueError('confidence must be between 0 and 1')
        return round(v, 2)  # 规范化精度
```

#### C. 回退机制

```python
class DeterministicFallback:
    """非确定性响应的确定性回退"""
    
    def process_with_fallback(self, input_data):
        try:
            # 尝试确定性路径
            return self.deterministic_path(input_data)
        except NonDeterministicError:
            # 回退到安全默认值
            return self.safe_default_response(input_data)
```

## 五、核心洞察

### Key Insight 1: 拥抱可控的非确定性

完全消除非确定性：
- ❌ 不可能（LLM本质）
- ❌ 不必要（创造力需要）
- ❌ 不经济（成本过高）

正确的做法：
- ✅ 区分关键路径和非关键路径
- ✅ 对关键路径施加确定性约束
- ✅ 对非关键路径保留灵活性

### Key Insight 2: 测试即文档

对于Agent系统：
- 测试定义了"正确行为"的边界
- 测试记录了系统的契约
- 测试是唯一的可靠性保证

### Key Insight 3: 监控优于测试

在不确定性的世界中：
- 实时监控比离线测试更重要
- 分布漂移检测比单元测试更关键
- 用户反馈是最真实的测试
