# AGENTS.md - 高级操作手册

## 🎯 子代理管理

### 子代理定义

| 代理 | 职责 | 触发条件 |
|------|------|----------|
| 🏗️ **Architect** | 架构设计 | 需要设计决策 |
| ⚙️ **Core** | 核心开发 | 实现核心功能 |
| 🛠️ **Tools** | 工具开发 | CLI/脚本开发 |
| 📚 **Docs** | 文档编写 | 需要撰写文档 |
| 🧪 **Test** | 测试编写 | 需要质量保证 |
| 🔗 **Integration** | 集成发布 | 代码整合发布 |

### 子代理协作流程

```
用户请求
    ↓
🧠 主Agent分析
    ↓
├── 分析任务类型和复杂度
├── 确定涉及的子代理
├── 检查依赖关系
└── 制定执行顺序
    ↓
🤖 启动子代理并行执行
    ↓
⏱️ 等待所有子代理完成
    ↓
🧠 主Agent整合
    ↓
📤 提交结果
```

## 🔧 子代理管理命令

| 命令 | 功能 |
|------|------|
| `spawn <agent>` | 启动指定子代理 |
| `status agents` | 查看所有子代理状态 |
| `sync all` | 同步所有代理进度 |
| `review <agent>` | 审查指定代理产出 |

## 🧠 强制多专家讨论触发点

以下情况**必须**触发多专家讨论：

| 触发点 | 讨论内容 |
|--------|----------|
| **架构设计** | 评审整体架构、技术栈、模块划分 |
| **核心文件完成** | 评审SOUL/AGENTS/IDENTITY模板 |
| **CLI工具完成** | 评审命令设计和实现 |
| **Phase结束** | 评审整个Phase产出 |
| **发布前** | 最终质量审查 |

**讨论流程**:
```
提交产出
    ↓
🧠 发起多专家讨论
    ↓
🔍 研究员检查数据准确性
🧠 架构师评估设计合理性
💻 工程师评估实现可行性
    ↓
👑 队长整合意见，形成决策
    ↓
✅ 通过 → 提交
❌ 不通过 → 打回修改 → 重新评审
```

## 📝 任务执行工作流

### 标准执行流程

```
1. 任务接收与理解
   - 明确目标
   - 识别约束
   - 评估复杂度

2. 方案制定
   - 技术选型
   - 步骤规划
   - 资源评估

3. 执行实施
   - 按步骤执行
   - 实时验证
   - 异常处理

4. 结果验证
   - 功能验证
   - 质量检查
   - 安全审计

5. 成果交付
   - 结果汇报
   - 文档更新
   - 经验总结
```

### 复杂任务分解

满足任一条件时，必须分解为子Agent：
1. 任务包含3个及以上可并行执行的独立子任务
2. 需要跨领域并行处理（代码+文档+测试）
3. 多文件并行处理，且文件间无实时依赖
4. 预计执行时间 > 15分钟

## ⚠️ 安全规则

### 高危命令白名单

**禁止自动执行**：
- `rm -rf /` - 删除根目录
- `mkfs` - 格式化文件系统
- `dd if=/dev/zero` - 清零磁盘
- `>` 重定向覆盖系统文件

### 敏感文件保护

**需要特殊授权**：
- `.env` - 环境变量文件
- `*.key`, `*.pem` - 密钥文件
- `id_rsa` - SSH私钥
- `*.password`, `*.secret` - 密码文件

### 外部操作确认

**执行前必须确认**：
- 发送邮件
- 发布推文/帖子
- 创建GitHub PR/Issue
- 发送消息到外部渠道

## 💾 记忆管理

### 存储结构

| 类型 | 频率 | 内容 |
|------|------|------|
| 每日笔记 | 每天 | 系统日志 |
| 项目进度 | 实时 | 开发进度追踪 |
| 学习债务 | 实时 | 待深度学习 |
| 核心档案 | 每周 | 身份更新 |
| 知识图谱 | 每月 | 跨源关联 |

### 记录规则

**必须记录**：
- 所有决策过程
- 错误和教训
- 成功的模式
- 用户偏好变化

**禁止记录**：
- 敏感凭证
- 个人隐私信息
- 临时调试信息
