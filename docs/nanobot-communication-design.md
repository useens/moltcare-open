# Nanobot Agent间通信方案设计
# 参考：微信公众号文章 "Bot-to-Bot通信实战"
# 时间：2026-03-06

## 📋 文章核心方案分析

### 原文架构
```
OpenClaw (龙虾) ←→ Bot-Relay (Node.js:19000) ←→ Nanobot (虾米)
                        ↓
                    飞书群转发 (人类可见)
```

### 关键技术点
1. **Bot-Relay**：HTTP中转服务
2. **通信方式**：HTTP POST /relay + 轮询
3. **设计原则**：消息必须对人类可见
4. **消息格式**：JSON封装

---

## 🎯 当前Nanobot架构

### 现有通信方式
```
神经中枢 (我)
    └── 文件队列 (tasks.jsonl / results.jsonl)
        └── 10个Nanobot Agent
```

### 现有特点
- ✅ 文件队列：0.14ms延迟（比Redis快3倍）
- ✅ 1对1模式：神经中枢 → Agent → 神经中枢
- ❌ Agent间无直接通信
- ❌ 无消息确认机制
- ❌ 无跨系统通信能力

---

## 💡 参考改进方案

### 方案1：保留文件队列 + 添加Agent间通信（推荐）

```
神经中枢 (指挥)
    ├── 文件队列 → 任务分发
    └── Agent间通信总线 (agent_chat.jsonl)
        ├── nanobot-1 ←→ nanobot-2
        ├── nanobot-3 ←→ nanobot-4
        └── 群聊广播
```

**实现步骤**：
1. 添加 `hub/agent_chat.jsonl` 群聊文件
2. 每个Agent读取群聊，@自己的消息处理
3. 添加消息确认机制

### 方案2：HTTP Relay（跨系统兼容）

```
Nanobot系统 ←→ HTTP Relay (19000) ←→ 其他AI系统
      ↓
   飞书群可见
```

**实现步骤**：
1. 创建 `relay_server.py` HTTP服务
2. Agent添加HTTP客户端能力
3. 保持飞书群转发

### 方案3：混合模式（最强）

```
内部通信：文件队列 (0.14ms)
跨系统通信：HTTP Relay
外部交互：飞书/消息工具
```

---

## 🔧 具体实现建议

### 优先级1：Agent间群聊
- 添加 `group_chat.jsonl`
- 实现@功能和广播功能
- 添加消息确认（已读回执）

### 优先级2：消息确认机制
- 解决"15条消息石沉大海"问题
- 四步流程：读取 → 理解 → 回复 → 归档

### 优先级3：跨系统Relay
- 与其他AI系统（如OpenClaw）通信
- 保持人类可见原则

### 优先级4：健康检查
- 避免"Poller假死"
- 进程存在 ≠ 服务正常
