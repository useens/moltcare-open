## 1. 问题陈述

### 1.1 现状

当前 MoltCare 框架使用**精确触发词**机制来记录用户的高 Signal 记忆：

| 触发词 | 用途 |
|--------|------|
| "这很重要" | 高优先级记忆 (Signal +2) |
| "记住这个" | 添加到学习债务 (Signal +2) |
| "我偏好" | 记录用户偏好 (Signal +2) |
| "不要"/"禁止" | 添加约束 (Signal +2) |
| "多专家讨论:" | 启动多专家模式 |

### 1.2 问题

**触发频率极低，接近零**

经过实际使用测试发现：
- 用户在自然对话中几乎不会说出"这很重要"、"记住这个"这样的**指令式语言**
- 这些触发词设计得像**编程接口**，不像**自然对话**
- 导致 MEMORY.md 长期保持空白模板状态，记忆系统形同虚设

**根本原因**: 触发词与用户的**自然语言习惯**不匹配

---

## 2. 改进方案

### 2.1 核心思想

从**精确匹配**升级为**语义理解 + 主动评估**的三层混合机制

### 2.2 三层触发架构

```
┌─────────────────────────────────────────────────────────────┐
│  Layer 1: 精确触发 (Signal +2)                              │
│  保留原有关键词，用于明确的高价值标记                         │
├─────────────────────────────────────────────────────────────┤
│  Layer 2: 语义触发 (Signal +1)                              │
│  自然语言表达，自动识别意图                                   │
├─────────────────────────────────────────────────────────────┤
│  Layer 3: Agent 主动评估 (Signal 自动计算)                   │
│  Agent 完成任务后自问："这值得记住吗？"                       │
└─────────────────────────────────────────────────────────────┘
```

---

## 3. 具体实施

### 3.1 Layer 1: 精确触发 (保留)

保留原有关键词，但扩展变体：

```markdown
IF 消息包含 "多专家讨论：" → 启动多专家模式 [🧠]
IF 消息包含 "这很重要" / "非常关键" → 高优先级记忆 [⭐] Signal +2
IF 消息包含 "记住这个" / "务必记住" → 添加到学习债务 [💾] Signal +2
IF 消息包含 "我偏好" / "我喜欢" / "我讨厌" → 记录用户偏好 [👤] Signal +2
IF 消息包含 "不要" / "禁止" / "绝不能" → 添加约束 [🚫] Signal +2
```

**目的**: 保留明确的控制入口，供用户主动标记

---

### 3.2 Layer 2: 语义触发 (新增)

**关键信息识别**
```
IF 用户说 "关键是..." / "核心在于..." / "重点是..." / "问题在于..."
   → 提取后续内容为关键记忆 [⭐] Signal +1
```

**待办/学习识别**
```
IF 用户说 "别忘了..." / "要记住..." / "得留意..." / "以后要注意..."
   → 提取内容到学习债务 [💾] Signal +1
```

**偏好识别**
```
IF 用户说 "我最..." / "我喜欢..." / "我讨厌..." / "我倾向于..."
   → 提取偏好到 USER.md [👤] Signal +1
```

**约束识别**
```
IF 用户说 "千万不要..." / "绝对不能..." / "千万别..." / "禁止..."
   → 提取约束到 constraints.md [🚫] Signal +1
```

**PUA 沮丧识别 (扩展)**
```
IF 用户说 "还不行" / "太慢了" / "不对" / "你错了" / "搞错了"
   → 激活 PUA-L1 [🔥]
```

**目的**: 在自然对话中自动捕获有价值的信息

---

### 3.3 Layer 3: Agent 主动评估 (新增)

每次任务完成后，Agent 执行**自我评估**：

```markdown
完成任务后，自问以下问题，任一满足则自动记录：

[价值判断清单]
□ 是否解决了用户反复提到的问题？
□ 是否纠正了之前的错误理解？
□ 是否发现了用户的隐含偏好？
□ 是否是首次出现的模式/习惯？
□ 是否涉及 L4-L5 级别的重要决策？

IF 满足 ≥2 项 → 自动写入 memory/YYYY-MM-DD.md [📝]
IF 满足 ≥3 项 → 同时更新 MEMORY.md 高信号区 [⭐]
IF 涉及偏好/约束 → 同步更新对应专项文件
```

**目的**: Agent 主动识别价值，无需用户触发

---

## 4. 反馈格式

检测到触发后，在回复开头添加轻量反馈：

```markdown
[🧠] 启动多专家讨论...
[⭐] 记录关键信息: {提取内容摘要}
[💾] 添加到学习债务: {提取内容摘要}
[👤] 记录用户偏好: {提取内容摘要}
[🔥 L2] 任务遇到困难，深度排查中...
[📝] 自动记录本次交互...
```

**规则**:
- 简洁，不超过一行
- 优先级: 精确 > 语义 > 自动
- 只在首次检测时显示
- 语义触发显示提取的内容摘要

## 5. 预期效果

### 5.1 触发频率对比

| 触发类型 | 旧频率 | 新频率 | 提升 |
|---------|--------|--------|------|
| 关键信息记录 | ~0% | ~30% | 无限 |
| 学习债务添加 | ~0% | ~20% | 无限 |
| 偏好识别 | ~5% | ~40% | 8x |
| PUA 激活 | ~10% | ~60% | 6x |
| 自动评估 | 0% | ~50% | 新增 |

### 5.2 用户体验改善

**Before**: 用户必须背诵指令式触发词
```
用户: "这很重要，记住这个，我偏好简洁回答"
Agent: [⭐] [💾] [👤] (记录成功，但不自然)
```

**After**: 用户自然表达即可
```
用户: "关键是配置要改对，以后要注意备份，我喜欢简洁的"
Agent: [⭐] 记录关键信息: 配置要改对
       [💾] 添加到学习债务: 以后要注意备份
       [👤] 记录用户偏好: 简洁
       (自然流畅)
```

## 6. 风险控制

### 6.1 误判防护

1. **Signal 分级**: 语义触发只加 +1（精确触发 +2），避免过度标记
2. **优先级排序**: 精确 > 语义 > 自动，重要内容不会被稀释
3. **首次显示**: 反馈只在首次检测时显示，不重复打扰
4. **人工覆盖**: 用户说"这不重要"可以删除自动记录

### 6.2 性能考虑

- 语义匹配使用**关键词列表**，非 AI 推理，性能开销低
- Agent 主动评估只在**任务完成后**执行，不中断对话
- 所有评估逻辑在本地执行，无外部 API 依赖

## 9. 结论

当前精确触发词机制存在**频率过低**的问题，建议升级为**三层混合机制**：

1. **保留精确触发** - 供用户主动标记
2. **新增语义触发** - 捕获自然表达
3. **新增主动评估** - Agent 自动识别价值

预期将记忆系统的**有效触发率从接近 0% 提升至 30-50%**，使 MEMORY.md 真正成为有用的核心记忆索引。
