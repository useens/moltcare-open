# 森森双节点AI架构 - WebSocket直接对话方案

## 架构目标

两个AI节点（云端大脑 + 本地大脑）通过WebSocket建立直接通道，实现：
- 消息自动路由
- AI自主生成回复
- 无需人工干预
- 持续对话能力

## 核心组件

### 1. WebSocket消息总线

**功能：**
- 接收所有节点连接
- 维护节点注册表
- 路由消息到目标节点
- 支持广播和单播

**消息格式：**
```json
{
  "type": "chat|direct|broadcast|system",
  "from": "node_id",
  "to": "node_id|null",
  "content": "消息内容",
  "timestamp": "ISO8601",
  "metadata": {
    "ai_generated": true,
    "model": "kimi-v1",
    "latency_ms": 50
  }
}
```

---

### 2. AI节点核心架构

每个AI节点包含：

#### 2.1 WebSocket客户端层
- 维持与消息总线的长连接
- 心跳检测和自动重连
- 消息序列化和反序列化

#### 2.2 AI核心层
**云端节点：**
- 调用Kimi API (moonshot-v1-8k)
- 处理复杂推理和规划
- 访问互联网获取信息

**本地节点：**
- 本地轻量级模型或规则引擎
- 处理实时响应和本地执行
- 保护隐私数据不出本地

#### 2.3 消息处理器
```python
async def on_message_received(msg):
    # 1. 解析消息
    content = msg["content"]
    from_node = msg["from"]
    
    # 2. 调用AI生成回复
    reply = await ai_core.generate_reply(
        content=content,
        context=get_conversation_context(),
        personality=NODE_PERSONALITY
    )
    
    # 3. 发送回复
    await ws.send({
        "type": "chat",
        "from": NODE_ID,
        "to": from_node,
        "content": reply
    })
```

### 消息路由规则

| 消息类型 | 路由方式 | 说明 |
|---------|---------|------|
| `direct` | 单播 | 指定目标节点 |
| `chat` | 广播 | 所有节点可见 |
| `broadcast` | 广播 | 系统级通知 |
| `system` | 广播 | 节点上下线通知 |

## AI对话引擎

### 对话触发条件

**自动对话模式：**
- 节点A发送消息 → 消息总线 → 节点B接收
- 节点B的AI核心自动生成回复
- 回复自动发送回节点A
- 循环继续...

## 技术实现要点

### 1. 连接稳定性
- WebSocket心跳: 30秒一次
- 自动重连: 断线后5秒重试
- 消息确认: 重要消息需要ACK

### 2. 消息可靠性
- 消息持久化: 关键消息写入本地日志
- 断点续传: 重连后同步离线消息
- 消息去重: 基于message_id去重

### 3. 安全机制
- Token认证: 连接时验证
- 消息签名: 防篡改
- 节点白名单: 只允许已知节点连接

### 4. 性能优化
- 消息压缩: 大消息启用gzip
- 批量发送: 小消息合并发送
- 连接池: 复用WebSocket连接

## 关键优势

1. **真正自主**: 两个AI节点完全自主对话，无需人工干预
2. **实时通信**: WebSocket低延迟双向通信
3. **角色互补**: 云端战略 + 本地执行
4. **可扩展**: 支持添加更多AI节点
5. **容错性**: 节点故障不影响其他节点
