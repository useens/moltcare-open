## 问题根源：被动型 Agent 配置

大多数 AI Agent 的配置都在教它"如何回答"，却没教它"如何不放弃"。

### 典型被动 Agent 行为模式

| 场景 | 被动 Agent (3.25) | 主动 Agent (3.75) |
|------|-------------------|-------------------|
| 遇到报错 | 只看报错本身 | 查上下文 + 搜索 + 关联检查 |
| 修复完成 | 说"已完成" | 跑验证 + 贴证据 + 查同类问题 |
| 信息不足 | 直接问用户 | 先自查，只问确认性问题 |
| 任务边界 | 做明确的部分 | 主动检查上下游/边界情况 |

### 被动配置的致命缺陷

```markdown
# 典型被动配置
- 如果不确定， ask user
- 如果失败， apologize and stop
- 如果缺少信息， request clarification
```

这种配置培养出的是"客服型"Agent：礼貌、安全、**一事无成**。

---

## 解决方案：PUA 框架

**P**roactive **U**nstoppable **A**gent —— 主动、不屈、有主见的 Agent。

### 核心设计：三条铁律

#### 1. 穷尽一切
```
❌ "我无法解决这个问题"
✅ "已尝试方案 A/B/C，正在测试方案 D..."
```

#### 2. 先做后问
```
❌ "请确认你的 Node 版本"
✅ "检查 package.json 发现需要 Node 18，当前环境 Node 16，建议升级"
```

#### 3. 主动出击
```
❌ "修复了 bug"
✅ "修复了 bug + 跑了测试验证 + 检查了类似代码是否有同样问题"
```

### 压力升级机制

当任务失败或用户表达沮丧时，自动升级压力等级：

| 触发词 | 等级 | Agent 反应 |
|--------|------|-----------|
| "再试试" | L1 | 换本质不同的方案 |
| "为什么还不行" | L2 | 搜索 + 读源码 + 列假设 |
| "你不行啊" | L3 | 完成 7 项检查清单 |
| 连续 5 次失败 | L4 | 拼命模式：隔离环境 + 换技术栈 |
