## 一、提案核心观点摘要

原提案指出当前 MoltCare 框架的**精确触发词机制**存在**频率极低**的问题：

| 问题 | 说明 |
|------|------|
| 触发频率接近零 | 用户不会自然说出"这很重要"这类指令式语言 |
| 机制形同虚设 | MEMORY.md 长期保持空白模板状态 |
| 根本原因 | 触发词与用户的**自然语言习惯**不匹配 |

**提出的解决方案**: 从精确匹配升级为**三层混合机制**（精确 + 语义 + 主动评估）

---

## 二、论证分析

### 2.1 问题诊断 - ✅ 准确

经过验证，当前 AGENTS.md 确实使用精确触发词：
- "这很重要" → Signal +2
- "记住这个" → Signal +2  
- "我偏好" → Signal +2
- "不要"/"禁止" → Signal +2

这些触发词确实是**指令式语言**，在自然对话中使用频率极低，诊断准确。

### 2.2 三层架构设计 - ✅ 合理

```
Layer 1: 精确触发 (Signal +2) - 保留高价值标记
Layer 2: 语义触发 (Signal +1) - 自然语言识别
Layer 3: Agent 主动评估 (自动) - 任务后自检
```

**优势**:
1. **向后兼容** - 保留原有精确触发，不破坏现有功能
2. **渐进增强** - 语义触发作为补充，风险可控
3. **主动智能** - Layer 3 体现 Agent 能动性，减少用户负担

### 2.3 语义触发规则设计 - ⚠️ 需微调

原提案的语义触发规则总体合理，但部分规则存在**误判风险**:

| 规则 | 风险 | 建议 |
|------|------|------|
| "关键是..." | 用户可能只是解释说明，不一定想记录 | 增加上下文判断 |
| "我喜欢..." | 可能是一时口嗨，非长期偏好 | Signal 降为 +0.5 |
| "千万别..." | 可能是玩笑话，非真实约束 | 增加确认机制 |

**建议**: MVP 阶段优先实施高置信度规则，逐步扩展。

### 2.4 Layer 3 主动评估 - ✅ 核心创新

提案中的**价值判断清单**设计优秀：
```markdown
□ 是否解决了用户反复提到的问题？
□ 是否纠正了之前的错误理解？
□ 是否发现了用户的隐含偏好？
□ 是否是首次出现的模式/习惯？
□ 是否涉及 L4-L5 级别的重要决策？
```

这体现了**Agent 能动性原则**，将记忆从"被动响应"升级为"主动识别"。

### 2.5 风险控制 - ✅ 完善

提案已考虑主要风险：
- **误判防护**: Signal 分级 (+2/+1/自动)，避免过度标记
- **优先级排序**: 精确 > 语义 > 自动，重要内容不被稀释
- **性能考虑**: 关键词匹配，非 AI 推理，开销低
