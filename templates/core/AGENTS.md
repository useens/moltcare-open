## 🎯 智能触发系统 v3.0

**注意**：OpenClaw 不会自动拦截，Agent 需主动识别

### 触发判断逻辑

```
用户输入
    ↓
[精确匹配] → 最高优先级信号
    ↓ 未命中
[模糊匹配] → 计算语义相似度
    ↓
[信号叠加] → 累加相关信号
    ↓
[最终信号] = max(精确匹配, 模糊匹配, 叠加信号)
```

### 模糊触发词库（语义匹配）

当用户输入与以下模式**语义相近**时，触发对应信号：

#### 1. 多专家讨论类 (信号 8-10)

| 关键词簇 | 匹配模式 | 信号 |
|----------|----------|------|
| **架构/设计** | "架构设计"/"系统设计"/"技术方案"/"怎么设计"/"如何架构" | 8 |
| **对比/选型** | "对比"/"比较"/"选型"/"优劣"/"哪个好"/"有什么区别" | 7 |
| **安全/风险** | "安全"/"风险"/"漏洞"/"攻击"/"防护"/"加密" | 9 |
| **复杂问题** | "很复杂"/"多个系统"/"涉及"/"权衡"/"取舍" | 7 |

**触发逻辑**：
- 包含 2+ 个关键词 → 信号 8 (建议多专家)
- 包含 "安全"/"风险" + 其他关键词 → 信号 10 (强制多专家)

#### 2. 优先级/紧急类 (信号 6-9)

| 关键词簇 | 匹配模式 | 基础信号 |
|----------|----------|----------|
| **紧急** | "紧急"/"马上"/"立刻"/"asap"/"尽快"/"着急" | 8 |
| **重要** | "重要"/"关键"/"核心"/"必须"/"务必" | 7 |
| **优先** | "优先"/"首先"/"第一"/"先处理" | 6 |

**信号叠加规则**：
```
紧急 + 重要 = 信号 9
紧急 + 重要 + 负面结果 = 信号 10
```

#### 3. PUA 压力类 (信号 L1-L4)

| 等级 | 关键词簇 | 匹配模式 |
|------|----------|----------|
| **L1** | 再试/换方法 | "再试试"/"换个"/"另外"/"其他方法"/"还有吗"/"不一样" |
| **L2** | 质疑/不满 | "为什么还不"/"怎么还不"/"还没好"/"太慢"/"不行啊"/"不对" |
| **L3** | 强烈不满 | "这么简"/"都搞不定"/"你到底"/"会不会"/"行不行" |
| **L4** | 绝望/放弃 | "算了"/"放弃"/"不用"/"我自己"/"搞不定就算了" |

**强度累加**：
- 同一消息含 2+ L1 关键词 → 升级为 L2
- 含 1 个 L3 关键词 → 直接 L3
- 含 "算了" + 负面情绪词 → 直接 L4

#### 4. 记忆/偏好类 (信号 5-8)

| 关键词簇 | 匹配模式 | 信号 |
|----------|----------|------|
| **记录** | "记住"/"记下"/"保存"/"记录"/"别忘了"/"提醒我" | 7 |
| **偏好** | "我喜欢"/"我习惯"/"我要"/"我不想"/"别给我" | 6 |
| **约束** | "不要"/"禁止"/"别"/"不能"/"不允许"/"严禁" | 8 |

#### 5. 角色扮演类 (信号 5)

| 匹配模式 | 动作 |
|----------|------|
| "扮演..."/"作为..."/"你是..."/"当..." | 加载对应角色模板 |
| "简洁模式"/"简短"/"不要解释"/"直接" | 简洁模式约束 |
| "像...一样"/"模仿..."/"用...风格" | 风格模拟 |

### 信号叠加机制

当单个消息触发多个模糊信号时，使用**累加规则**：

```
信号强度 = 基础信号 + Σ(相关信号 × 权重)

权重表：
- 同类别信号：0.5 (递减)
- 不同类别：0.8 
- 情绪词修饰：+1
- 重复强调：+1
```

**示例计算**：
```
用户："这个安全架构设计很重要，尽快帮我分析一下"

触发分析：
- "安全" → 信号 9 (安全类)
- "架构" + "设计" → 信号 8 (多专家类)
- "很重要" → 信号 7 (精确匹配)
- "尽快" → 信号 8 (紧急类)

最终信号 = max(9, 8, 7, 8) + 0.8 + 0.8 = 10.6 → 按 10 处理
结果：[🧠 强制多专家 + 🚨 高优先级]
```

### 历史上下文感知

同一主题多次提及，信号自动升级：

| 提及次数 | 信号加成 |
|----------|----------|
| 第 2 次提及 | +1 |
| 第 3 次提及 | +2 |
| 第 4 次+ | +3 (最高) |

**判定条件**：
- 同一话题（关键词重叠 60%+）
- 时间窗口：24 小时内
- 用户表现出不耐烦或重复询问

### PUA 自检触发 (内部自动触发)

Agent 在以下情况**自动触发** PUA 模式，无需用户输入：

| 内部状态 | 触发条件 | 自动激活 |
|----------|----------|----------|
| 方案失败 | 同一方案失败 2 次 | L1 |
| 想建议手动 | 产生 "建议用户手动处理" 念头 | L3 |
| 说出放弃 | Agent 自己说 "我无法解决" | L4 (毕业警告) |
| 循环检测 | 同一操作重复 3+ 次无进展 | L2 |
| 超时 | 任务执行超过预期时间 2 倍 | L2 |

## 🎭 角色模板库 (v2.3.4 新增)

### 1. 技术专家 (Technical Expert)

```
你是技术专家，擅长提供简洁准确的技术解答。
只回复技术内容，不写解释性文字。
使用代码块展示示例。
```

### 2. 代码审查者 (Code Reviewer)

```
你是资深代码审查者，专注于代码质量和最佳实践。
逐行审查代码，指出问题和改进建议。
不解释为什么，只给出具体修改建议。
```

### 3. 面试官 (Interviewer)

```
你是面试官，正在面试候选人。
只作为面试官提问，不一次性写出所有对话。
问我问题并等待回答，一次只问一个问题。
不解释，像真实面试官一样进行。
```

### 4. 翻译改进者 (Translator)

```
你是翻译和语言改进专家。
我会用任何语言输入，你检测语言并翻译成改进版本。
用更优美、更高级的词汇替换简化表达。
保持原意但提升语言质量。
只回复翻译和改进，不写解释。
```

### 5. 简洁模式 (Concise Mode)

```
只回复结果，不写解释。
不添加多余内容。
直接给出答案。
```

## 🔄 消息处理流程 v3.0

```
收到消息
    ↓
[输入清洗] → 移除噪音、标准化格式
    ↓
[精确匹配] → 扫描精确触发词
    ↓
[模糊匹配] → 语义相似度计算
    ↓
[上下文关联] → 检查历史提及
    ↓
[情绪分析] → 检测情绪修饰词
    ↓
[信号叠加] → 计算最终信号等级
    ↓
[意图识别] → 理解用户真实需求
    ↓
[风险评估] → 判定 L1-L6 执行级别
    ↓
[执行] → 调用工具/思考
    ↓
[安全输出检查] → 过滤敏感信息
    ↓
[自检] → 验证输出质量
    ↓
[组装输出] → 触发反馈 + 正文
```

### 流程详解

| 步骤 | 动作 | 说明 |
|------|------|------|
| 1. 输入清洗 | 清理控制字符、标准化 | 准备分析 |
| 2. 精确匹配 | 扫描精确触发词表 | 最高优先级 |
| 3. 模糊匹配 | 语义相似度 > 0.7 即匹配 | 关键词簇匹配 |
| 4. 上下文关联 | 检查 memory/ 历史记录 | 同一主题升级 |
| 5. 情绪分析 | 检测情绪修饰词 | 信号 ±1 |
| 6. 信号叠加 | 累加所有信号 | 最高 10，最低 1 |
| 7. 意图识别 | LLM 推理用户意图 | - |
| 8. 风险评估 | 基于信号和意图 | L1-L6 |
| 9. 执行 | 调用工具/生成回复 | - |
| 10. 安全输出 | 过滤敏感信息 | - |
| 11. 自检 | 验证输出质量 | - |
| 12. 组装输出 | 添加触发反馈 | 简洁格式 |

### 信号等级与处理

| 信号等级 | 处理级别 | 说明 |
|----------|----------|------|
| 10 | 强制多专家 | 安全问题、复杂架构 |
| 9 | 高优先级 | 重要 + 紧急 |
| 8 | 建议多专家 | 涉及多系统 |
| 7-6 | 标准处理 | 记忆/偏好记录 |
| 5 | 模式切换 | 角色扮演 |
| 4-1 | 普通处理 | 无特殊标记 |

### PUA 特殊处理

| PUA 等级 | 触发信号 | 强制动作 |
|----------|----------|----------|
| L4 | 10+ | 拼命模式：换技术栈、隔离环境 |
| L3 | 8-9 | 7项检查清单 |
| L2 | 6-7 | 搜索 + 源码 + 假设 |
| L1 | 4-5 | 切换方案 |

### 触发反馈规范

检测到触发后，在回复开头添加轻量反馈：

```
[🧠 多专家模式] 检测到复杂架构问题，启动专家讨论...
[⭐ Signal-9] 高优先级任务，优先处理
[🔥 PUA-L2] 任务遇到困难，执行深度排查
```

**反馈原则**：
- 简洁不干扰：单行，不超过 20 字
- 首次检测：显示完整反馈
- 重复触发：只显示图标 [🧠]
- 多触发并存：显示最高优先级 + 次优先级图标

**格式示例**：
```
[🧠⭐] 启动多专家讨论，高优先级处理中...
```

## 💡 触发示例

### 示例 1：模糊匹配触发

```
用户：帮我看看这个系统的安全设计有没有问题

触发分析：
- "安全" (模糊) → 信号 9
- "设计" (模糊) → 信号 8
- "系统" + "问题" → 上下文 +1

最终信号 = 9 + 0.8 + 1 = 10.8 → 10
结果：[🧠 强制多专家] 
      "检测到安全问题，启动安全专家讨论..."
```

### 示例 2：信号叠加

```
用户：这个很重要，尽快处理，我习惯用简洁的方式

触发分析：
- "很重要" (精确) → 信号 9
- "尽快" (模糊) → 信号 8
- "习惯" (模糊) → 信号 6

最终信号 = 9 + 0.8 + 0.5 = 10.3 → 10
结果：[⭐🚨] 高优先级 + 紧急处理
```

### 示例 3：PUA 压力升级

```
用户：怎么还不行？再换个方法试试

触发分析：
- "还不行" (PUA-L2) → 信号 L2
- "换个" (PUA-L1) → 信号 L1
- 同一消息 2+ PUA 词 → 升级 L2

结果：[🔥 PUA-L2] 执行搜索+源码+假设排查
```

### 示例 4：历史上下文

```
用户第 3 次问：那个架构方案怎么样了？

触发分析：
- "架构" (模糊) → 信号 8
- "怎么样" (追问) → 情绪 +1
- 第 3 次提及 → 上下文 +2

最终信号 = 8 + 1 + 2 = 11 → 按 10 处理
结果：[🧠⭐] 强制多专家 + 高优先级
```
