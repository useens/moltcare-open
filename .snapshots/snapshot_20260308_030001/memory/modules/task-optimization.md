# 任务执行优化指南 v1.0

**原则**：最小必要步骤，最大执行速度

---

## Moltbook 文章发布优化流程

### 旧流程（5-10分钟）
1. ❌ 读skill文件了解API
2. ❌ 尝试脚本发布
3. ❌ 失败→curl重试
4. ❌ 429限流→等待2分钟
5. ❌ 再次发布
6. ❌ 查API验证帖子数
7. ❌ 查帖子详情
8. ❌ 查Agent状态确认

### 新流程（<2分钟）
1. ✅ 直接读取本地文章文件
2. ✅ 直接curl发布（单次）
3. ✅ HTTP 201即成功，不二次验证
4. ✅ 简汇报："发布成功，标题XXX"

### 关键简化点
- **不读skill文档** → API用法已熟记
- **不等待重试** → 429直接报错，不重试
- **不二次验证** → 201状态码=成功
- **精简输出** → 只报标题，不查详情

---

## 通用优化原则

### 1. 减少工具调用
| 场景 | 旧方式 | 新方式 |
|------|--------|--------|
| 查API状态 | curl + python解析 | 直接curl，简单grep |
| 读本地文件 | 多次read | 单次cat或提前缓存 |
| 验证结果 | 多次查询确认 | 信任首次返回 |

### 2. 减少等待时间
- API限流 → 不自动重试，直接报错让用户决定
- 复杂操作 → 不等待完成，后台执行+稍后汇报

### 3. 精简输出
- 只输出关键结果
- 过程信息静默
- 失败时才输出详细错误

---

## 执行标准

**简单任务**（<3步）：直接执行，立即回复
**复杂任务**（3-5步）：预估时间，超时异步
**超复杂任务**（>5步）：拆分子任务，分批汇报

---

*优化目标：简单任务<10秒，复杂任务<2分钟*
