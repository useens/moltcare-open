# 系统智能精简路线图

> 🗺️ **分阶段实施计划** | 目标: 从230个脚本精简到<50个  
> **原则**: 安全优先，可回滚，不影响核心功能

---

## 阶段一: 紧急清理 (第1-2天)

### 目标
- 立即回收 1.5GB+ 存储空间
- 删除明显废弃的脚本
- 建立安全清理流程

### 任务清单

#### 1.1 清理.trash目录 (30分钟)
```bash
# 操作前备份清单
ls -la /root/.openclaw/workspace/.trash/2026-02-13/ > /root/.openclaw/workspace/memory/self-pruning/trash-manifest-20260216.txt

# 移动到归档 (保留30天)
mv /root/.openclaw/workspace/.trash/2026-02-13 /root/.openclaw/workspace/archives/trash-2026-02-13

# 30天后自动删除 (添加到cron)
```

**预期回收**: ~500KB代码 + 清理视觉负担

#### 1.2 删除重复脚本对 (15分钟)
```bash
# 重复对1: minimal-reporter
rm /root/.openclaw/workspace/scripts/minimal_reporter_v10.py  # 保留-版本

# 重复对2: token-optimizer
rm /root/.openclaw/workspace/scripts/token_optimizer_v10.py   # 保留-版本

# 重复对3: 根目录测试脚本
rm /root/.openclaw/workspace/test_vector_integration.py
rm /root/.openclaw/workspace/test_vector_queries.py
```

**预期回收**: ~50KB + 减少困惑

#### 1.3 备份清理 (15分钟)
```bash
# 只保留最近3个备份
cd /root/.openclaw/workspace/backups
ls -t *.tar.gz | tail -n +4 | xargs rm -f

# 预期保留:
# - workspace_backup_20260216_070702.tar.gz (最新)
# - workspace_backup_20260216_063813.tar.gz
# - workspace_backup_20260216_063800.tar.gz
```

**预期回收**: ~1.5GB

#### 1.4 无效日志清理 (10分钟)
```bash
# 清空虚假的token日志
> /root/.openclaw/workspace/data/token-usage.log

# 清空超过7天的日志
find /root/.openclaw/workspace/logs -name "*.log" -mtime +7 -exec truncate -s 0 {} \;
```

**预期回收**: ~200KB

### 目标
- 合并重复功能的脚本

- 减少脚本数量到 ~150个

### 任务清单

#### 2.1 合并情报收集脚本 (2天)

**当前状态**:
```
collect-web-intel.py        (7.4KB)
collect-web-intel-fast.py   (6.9KB)
collect-web-intel-hyper.py  (7.4KB)
```

**合并方案**:
```python
# intel-collector.py (统一版本)
#!/usr/bin/env python3
"""统一情报收集器 - 支持多种模式"""

import argparse

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument('--mode', choices=['normal', 'fast', 'hyper'], default='normal')
    parser.add_argument('--sources', nargs='+', default=['hackernews', 'github', 'reddit'])
    args = parser.parse_args()
    
    if args.mode == 'fast':
        collect_fast(args.sources)
    elif args.mode == 'hyper':
        collect_hyper(args.sources)
    else:
        collect_normal(args.sources)
```

**操作步骤**:
1. 创建新的intel-collector.py
2. 测试所有模式
3. 删除旧脚本
4. 更新所有调用者

## 阶段四: 架构重构 (第15-30天)

### 目标
- 建立清晰的系统架构
- 分离测试与生产代码
- 建立脚本生命周期管理
- 最终目标: <50个核心脚本

### 任务清单

#### 4.1 目录结构重构

**新结构**:
```
/root/.openclaw/workspace/
├── scripts/
│   ├── core/           # 核心功能 (10个)
│   ├── monitoring/     # 监控相关 (5个)
│   ├── backup/         # 备份相关 (3个)
│   ├── intel/          # 情报收集 (3个)
│   └── maintenance/    # 维护任务 (5个)
├── tests/              # 所有测试代码
├── archive/            # 归档代码 (不活跃)
└── docs/               # 文档
```

#### 4.2 脚本生命周期管理

**建立流程**:
```
1. 需求 → 2. 设计 → 3. 开发 → 4. 测试 → 5. 上线 → 6. 监控 → 7. 下线
```

**下线标准**:
- 30天无调用
- 功能被新脚本替代
- 标记为deprecated

#### 4.3 建立统一接口规范

**所有新脚本必须遵循**:
```python
#!/usr/bin/env python3
"""
脚本名称: xxx
功能描述: xxx
作者: xxx
创建日期: xxx
最后更新: xxx
状态: active | deprecated | archived
"""

import argparse
import logging

# 统一日志配置
logging.basicConfig(...)

def main():
    parser = argparse.ArgumentParser()
    # 标准参数
    parser.add_argument('--verbose', '-v', action='store_true')
    parser.add_argument('--dry-run', action='store_true')
    args = parser.parse_args()
    
if __name__ == '__main__':
    main()
```

## 风险缓解计划

### 风险1: 误删仍在使用的脚本
**缓解措施**:
- 所有删除操作先移动到trash，保留30天
- 删除前grep全仓库确认无引用
- 关键操作人工review

### 风险2: 合并后功能异常
**缓解措施**:
- 每个合并操作都有完整测试
- 保留旧脚本直到新脚本稳定运行7天
- 建立快速回滚机制

### 风险3: 自动化流程中断
**缓解措施**:
- 每次修改前记录当前cron配置
- 修改后立即验证cron任务
- 建立自动化测试套件
