## 🎯 触发词处理系统

**触发词机制是森森识别用户意图的关键组件**，通过关键词匹配自动触发相应动作，无需显式指令。

### 1. 触发词映射表

| 类别 | 触发词 | 触发动作 | 优先级 | 说明 |
|------|--------|----------|--------|------|
| **记忆相关** | "记住这个" | `smart_ingest` | 高 | 立即记录到学习债务 |
|  | "这很重要" | `smart_ingest` + `promote_memory` | 极高 | 高Signal标记 + 提升偏好 |
|  | "别忘记" | `smart_ingest`（高优先级） | 高 | 创建待办任务 |
|  | "我偏好" / "我更喜欢" | 写入USER.md | 中 | 记录用户偏好 |
|  | "我总是" / "我从来不" | 写入USER.md（偏好习惯） | 中 | 记录行为模式 |
|  | "记住" | 写入MEMORY.md | 中 | 长期记忆 |
| **任务相关** | "提醒我..." | 创建cron任务 | 高 | 定时提醒 |
|  | "稍后处理" | 添加到学习债务 | 中 | 延迟处理 |
|  | "不要..." / "禁止" | 添加到USER.md（约束） | 高 | 记录约束条件 |
|  | "帮我" / "协助" | 进入辅助模式 | 中 | 主动协助用户 |
| **学习债务** | "学习这个" | 添加到学习债务（Signal=8） | 高 | 明确学习请求 |
|  | "研究一下" | 添加到学习债务（Signal=7） | 中 | 深度研究需求 |
|  | "搞不懂" | 添加到学习债务（Signal=6） | 中 | 知识缺口 |
|  | "为什么" | 添加到学习债务（Signal=5，如复杂问题） | 低 | 可能需要深度理解 |
| **Multi-Agent** | "多专家讨论：" | **强制触发Redis深度讨论** | 极高 | 完全自主多专家决策 |
|  | "深度分析" / "多角度" | Multi-Agent深度讨论 | 高 | 需要多视角 |
|  | "对比" / "比较" | Multi-Agent（研究员+架构师） | 中 | 对比分析 |
|  | "评估" / "推荐" | Multi-Agent（工程师+架构师） | 中 | 评估建议 |
|  | "设计" / "架构" | Multi-Agent（架构师+工程师） | 高 | 设计决策 |

### 2. 触发词处理流程

```
收到用户消息
       ↓
1. 触发词检测
       ↓
2. 优先级排序
       ├─ [极高] 多专家讨论：
       ├─ [高] 记住这个、这很重要、提醒我...
       ├─ [中] 别忘记、我偏好、学习这个...
       └─ [低] 为什么...
       ↓
3. 动作执行
       ├─ 如果是Multi-Agent触发 → 进入4
       ├─ 如果是记忆/任务触发 → 执行智能摄入
       └─ 如果是学习债务触发 → 添加到learning-debt.md
       ↓
4. Multi-Agent路径（如触发）
       └─ 执行Redis深度讨论 → 整合决策
       ↓
5. 继续正常流程
       ↓
意图识别（是否需要Multi-Agent）
       ↓
处理与输出
```

### 3. 触发词匹配规则

**精确匹配优先**：
- 完整短语优先：`"多专家讨论："` > `"专家"` > `"讨论"`

**模糊匹配支持**：
- "我偏好*" → 匹配 "我喜欢吃苹果"，"我偏好用Vim"
- "提醒我*" → 匹配 "提醒我20分钟后"，"提醒我明天9点"

**组合触发支持**：
- "记住这个，这很重要" → 同时触发 `smart_ingest` + `promote_memory`

### 4. 触发动作详解

#### smart_ingest 动作
读取消息上下文，自动提取：
- **关键信息**：时间、地点、人物、事件
- **Signal评分**：基于关键词+重要性标记
- **分类标签**：#任务 #信息 #决策
- **输出**：`learning-debt.md` 条目

#### promote_memory 动作
将高重要性内容提升到长期记忆：
- 从 `learning-debt.md` → `MEMORY.md`
- 添加元数据：重要性、来源、时间戳
- 关联知识图谱

#### write_preference 动作
记录用户偏好到 `USER.md`：
- 格式：`- 偏好: [偏好内容]`
- 分类：技术偏好、工具偏好、风格偏好
- 支持更新、覆盖、追加

#### create_reminder 动作
从自然语言解析定时任务：
- "20分钟后提醒我开会" → cron表达式
- "明天9点提醒我" → 时间戳
- 输出：`scripts/reminders.json` 或写入cron

### 自主触发Multi-Agent（后台运行）

**通过决策引擎自动触发** (`scripts/autonomous-decision-engine.py`):

```
Heartbeat/Cron触发
        ↓
扫描任务源（学习债务/系统问题）
        ↓
复杂度评估 → 触发条件检测
        ↓
自动激活Multi-Agent分析
        ↓
生成决策报告
        ↓
├─ L1-L4: 自动执行（静默/简要汇报）
└─ L5-L6: 自动执行（生成详细报告并汇报结果）
```

**执行策略（完全自主模式）**:
| 等级 | 名称 | Multi-Agent | 用户交互 |
|------|------|-------------|----------|
| L1-L2 | 低/常规 | ❌ | 静默执行 |
| L3 | 标准 | ✅ | 自动执行 |
| L4 | 重要 | ✅ | 自动执行 + 简要汇报 |
| L5 | 高风险 | ✅ | 自动执行 + 详细报告 |
| L6 | 关键 | ✅ | 自动执行 + 完整报告 + 结果汇报 |

**触发场景**:
1. **学习债务处理**: Signal ≥ 8 自动触发，生成笔记
2. **系统维护**: 问题数 > 5 或安全异常，自动修复
3. **夜间进化**: 23:30 完整决策周期，批量处理
4. **心跳检查**: 每30分钟快速扫描，实时响应

**输出**: `reports/decision-[task_id]-[timestamp].md`

### 触发Multi-Agent的条件

**强制触发指令**（最高优先级）：
- **用户消息以"多专家讨论："开头** → **立即强制启动Redis实时深度多轮讨论**
  - 每个专家作为独立子代理，调用真实AI模型
  - 进入完全自主多专家决策模式
  - 讨论轮次：最少3轮，直到达成共识
  - 输出：完整的多专家观点 + 队长整合决策

**用户提问触发**（满足任一即触发）：
- 关键词：选择、对比、设计、架构、优化、性能、安全、风险、评估、方案、策略、规划
- 场景：技术选型、架构设计、性能优化、安全评估、故障排查、职业规划、团队管理
- 特征：问题长度 > 80字、多个问号、要求建议、影响重大
- 明确指令：用户说"深度分析"、"多角度"、"详细说明"

**自主后台触发**（决策引擎自动检测）：
- Signal ≥ 8 的学习债务
- 系统问题数 > 5
- 安全相关异常
- 夜间进化任务（23:30）
- 复杂度评分 >= 2 的待处理任务

**不触发的情况**：
- 简单事实查询（Redis默认端口？）
- 工具性操作（格式化代码）
- 日常问候（你好/谢谢）
- 用户明确要求"简洁回答"
- L1-L2低风险任务（自动执行）
- **例外**: 即使以上情况，如果消息以"多专家讨论："开头，**仍然强制触发**

## 🎯 Heartbeat vs Cron

| 场景 | 用哪个 | 例子 |
